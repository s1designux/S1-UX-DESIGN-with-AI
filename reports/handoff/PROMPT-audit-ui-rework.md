## 프롬프트

별도 폴더에서 해줘 — Figma 설치/검수기 플러그인의 **검수 화면을 아예 다시 짜는** 작업이야. 이미 만들어 둔 폴더가 있으니 새로 만들지 말고 `.claude/worktrees/ui-rework`(가지 `worktree-ui-rework`)에서 이어서 해.

### 배경 (읽고 시작해)

바로 앞 작업에서 **검수기의 «판단»은 고쳤다**(커밋 `5dde217`). 지금 검수기는 글자 유사도로 짐작하기 전에 river 결정표를 먼저 본다:

- 레거시 126세트의 답을 미리 구워 플러그인에 실었다 — 정해짐 88 · 아직 안 정함 34 · 교체 대상 아님 4. 생성물은 `plugins/figma-vars-installer/src/legacy-map-data.ts`(**손편집 금지**, 다시 굽기 `npm run legacy:bake`), 정본은 `reports/legacy-crosswalk-board/crosswalk.json`, 최신인지는 **Gate 52** 가 검사한다.
- 화면은 그 답을 세 갈래로 보여준다 — **정해짐(초록) / 아직 안 정함(노랑) / 교체 대상 아님(회색)**. 결정 카드는 고르는 칸을 접어 두고, 근거를 사람 말 한 줄로 보여준다.
- 모바일 화면을 검수하면 PC 전용 변형을 목록에서 뺀다(`[전부 보기]` 로 되돌림). 매체 판정은 부품에 걸린 결정 표결(2표 이상·2배 이상)과 화면 폭(600)이 **서로 맞을 때만** 쓴다.
- 🤖 `component-verifier` 독립 검증을 3회 돌려 지적 5건을 전부 닫았다. 상세는 커밋 메시지에 다 있다 — `git show 5dde217` 로 읽어라.

**이번 작업은 «판단»이 아니라 «화면»이다.** 지금 화면은 옛 구조(교체 후보 카드 목록) 위에 갈래 표시를 덧댄 모양이라, river 가 "아예 고쳐서 테스트해볼 수 있게" 하자고 했다.

### 먼저 할 일 — river 에게 물을 것

river 는 **무엇을 어떻게 바꿀지 아직 말하지 않았다.** 착수 전에 지금 화면을 보여 주고 불편한 곳을 받아라. 추측으로 다시 그리지 마라.

물을 때 이렇게 물어라(비개발자 UX 디자이너에게 코드 약어를 던지지 않는다):

1. 지금 화면에서 가장 거슬리는 곳이 어디인가 — 카드가 길다 / 무엇을 눌러야 할지 모르겠다 / 순서가 이상하다 / 한 화면에 너무 많다 …
2. 검수를 마칠 때까지의 흐름이 몇 단계였으면 하는가(지금은 검사 → 목록에서 하나씩 교체).
3. 「모두 교체」 같은 일괄 처리를 어디까지 허용할 것인가.

### 알고 있어야 할 것 (화면을 만질 때)

- 화면 정본은 `plugins/figma-vars-installer/src/ui.html` 한 장(약 2,800줄). CSS·HTML·JS 가 한 파일에 있고, 플러그인은 `tokens.css` 를 못 쓰므로 **토큰이 가리키는 실제 값을 그대로 적는다**(기존 주석 참고).
- 화면이 받는 것: `renderInspectionResult`(검사 결과) · `build-improved-result`(개선안). 두 입구 모두 `manualCandidates`(판정 갈래가 붙은 카드)·`modules`(부품 묶음)·`diagnostics`(매체·이름 중복)를 준다. 데이터 모양은 `audit-engine.ts` 의 `ManualMapCandidate`·`ModulePart`·`SwapDiagnostics` 를 보면 된다.
- **Figma 없이도 화면을 볼 수 있다.** 임시 하네스를 만들어 예시 데이터를 넣고 `node scripts/render-shot.js "<파일>" <출력.png> --full-page` 로 렌더해 눈으로 본다(앞 작업에서 쓰던 방법 — 임시 파일은 커밋하지 않는다). **raw chrome 명령은 금지**(안 끝난다).
- 실제 플러그인에서 보려면 **다시 등록해야 한다** — `npm run installer:build` 후 Figma 에서 플러그인 재등록/재실행.

### 꼭 지킬 것

- **판단을 건드리지 마라.** 이번 작업은 화면이다. 결정표·매체 판정·갈래 판정 로직을 바꾸려면 그 이유를 river 에게 먼저 올려라.
- **정본에 없는 이름을 만들지 마라**(하드룰 H6②). 정본 이름 사전은 `registry/components/component-facts.json` 의 `variantAxes` 하나뿐이다.
- **자동 교체를 넓히지 마라.** 결정이 있는 것만 정해지고, 나머지는 사람이 고른다.
- **화면을 건드렸으면 렌더 1회 확인 의무.** 검사기 통과로 시각 검증을 대체하지 않는다.
- **검증은 분리한다** — 만든 자 ≠ 검증하는 자. 🤖 `component-verifier` 를 실제 spawn 해서 대조시켜라. 화면 구조를 다시 짜는 일이라 self-certify 하지 마라.
- 보고는 river 규칙대로 — 굵은 결론 한 줄 먼저 · 쉬운 말 · 10줄 안팎 · **작업 중 중간 보고 0회**. 신규를 만들 때는 끝까지 혼자 가지 말고 **중간에 화면 안을 보여주고 확인받는다.**

### 기계검사 (끝내기 전 전부 초록이어야 함)

| 명령 | 무엇 |
|---|---|
| `npm run installer:check` | 플러그인 타입 검사 |
| `npm run installer:build` | 플러그인 번들·zip |
| `npm run legacy:check` · `npm run legacy:selftest` | Gate 52 본체 + 적대 시험(앞 작업 것이 깨지지 않았는지) |
| `npm run gate:check` | 전체 검문소 |

> 검문소가 «크롬이 시간 안에 끝내지 못했습니다» 로 실패하면 렌더가 겹친 것이다 — 단독으로 다시 돌려 확인해라.

### 앞 작업에서 넘어온 미결 (이번에 정해도 되고 그대로 둬도 된다)

- **HD-1 — 이름이 겹칠 때.** 이 파일에 정본과 이름이 같은 세트가 둘 이상 있으면 검수기가 어느 쪽이 정본인지 가리지 못한다. 지금은 노란 줄로 «답이 뒤바뀔 수 있다» 고 알리기만 한다. (A) 그대로 알리기만 / (B) 그 이름들은 아예 «모름» 으로 내려 결정표를 쓰지 않기. 안 정하면 (A).
- **HD-2 — 모바일로 보는 화면 폭 기준 600.** ⭐ 가 정한 값이다. 더 좁히거나 넓힐지. 안 정하면 600 그대로.
- **⭐ 자가인증으로 남은 것** — 마지막 잔손질 3건(이름 겹침 알림 줄 · 접힘 문구와 메모 동선 · 닮은 정도 표기)은 4차 독립 검증이 도중에 멈춰 렌더 확인만 했다. 실제 플러그인 안에서 결정 카드의 [교체]가 눌리는지도 아직 사람 손으로 확인 전이다.

### 합치기

끝나면 `npm run wt:merge` 한 번으로 본 폴더에 합친다. 앞 작업(`worktree-verifier-upgrade`)도 아직 안 합쳐졌으니, 합치는 차례는 **앞 것 먼저**다.
