# Figma 화면 검수기 — 1차 정의 + 화면 와이어프레임

> 작성일: 2026-08-31 · 작성: river + Claude 논의 결과
> 목적: 다른 AI/세션에서 이어서 진행할 수 있도록 확정 사항을 옮겨 담은 문서
> 상태: **1차 범위·항목·처리방식·화면 시나리오 확정** / 판정 규칙 상세 문서화는 미착수

---

## 0. 배경 — 왜 이렇게 설계했나

- 그룹원이 **당장 쓸 수 있어야** 의미가 있는데, 지금 디자인 시스템에는 **Core 컴포넌트 + 기본 토큰**뿐이라 모든 프로젝트를 완벽히 판정할 수 없다.
- 헷징의 핵심은 커버리지를 늘리는 게 아니라 **검수기가 못 보는 영역을 대놓고 선언**하는 것.
  → **체크리스트 방식**을 채택했다. 리스트가 곧 판정 범위이므로, 리스트에 없는 것은 자동으로 "미판정(침묵)"이 되어 **오탐이 구조적으로 나지 않는다.**
- 승격 기준의 축은 커버리지가 아니라 **오탐율**이다. 오탐 한 번이면 그룹원은 다시 쓰지 않는다.

### 검수 대상
**항상 Figma 화면**(노드 스캔). 구현된 웹 화면은 1차 대상이 아니다.

## 1. 출시 단계

| 차수 | 판정 대상 | 결과의 무게 |
|---|---|---|
| **1차** | 토큰·텍스트 스타일 + **컴포넌트 치환(2차 일부 선도입)** | 제안·선택형, 차단 없음 |
| **2차** | 컴포넌트 규격 전반 (variant/상태/크기/오버라이드) | ❌ 등장, 비차단 |
| **3차** | 화면·패턴 단위, 디자인↔구현 대조 | 팀이 스스로 켜는 선택적 차단 |

### 승격 조건
- **1차 → 2차**: 항목당 오탐 신고 5% 미만 · 최소 2개 팀이 자발적으로 사용 · 컴포넌트 정본이 2차 항목을 판정할 만큼 확정
- **2차 → 3차**: 오탐 2% 미만 · 패턴 정본 확정 · 같은 화면 두 번 돌려 결과 동일(결정론)

### 후퇴 규칙
- 오탐 신고가 주 3건 이상인 **항목만** 리스트에서 뺀다. 도구 전체를 내리지 않는다.
- 뺀 항목은 정본 보완 후 재편입.

## 2. 1차 체크리스트 — 확정 (10개)

### 검사 순서: **컴포넌트 → 색 → 텍스트 → 그림자**

컴포넌트를 먼저 검사·치환한다. 컴포넌트로 교체하면 그 안의 색·텍스트가 정본 배선을 그대로 물고 들어오므로 **semantic 선택 문제가 애초에 발생하지 않는다.** 순서를 반대로 하면 토큰을 고쳐놓고도 컴포넌트 교체로 그 작업이 버려진다.

| 단계 | # | 항목 | ❌ 조건 | 처리 |
|---|---|---|---|---|
| **1. 컴포넌트** | 0 | 정본 컴포넌트로 대체 가능한 요소 | 직접 그린 요소가 정본 컴포넌트와 일치 | 선택 후 교체 |
| **2. 색** | 1 | 색이 변수 바인딩 | 하드코딩 색 | 자동 |
| | 2 | 색 계층 사용 | *아래 3단계 참조* | ⚠️ 허용·기록 |
| | 3 | 로컬 스타일 잔존 없음 | 라이브러리 아닌 로컬 색/텍스트 스타일 | 자동 |
| | 4 | 불투명도로 색 변형 없음 | 토큰 색 + opacity 80% 등 | 배경 알면 자동, 아니면 검출 |
| **3. 텍스트** | 5 | 텍스트에 text style 적용 | 직접 폰트 설정 | 자동 |
| | 6 | 폰트 크기가 text style에 정의된 크기 | 정의 밖 크기(15, 17 등) | **선택** |
| | 7 | text style 값을 덮어쓰지 않음 | 행간·자간·굵기 override | 자동(되돌리기) |
| | 8 | Pretendard | Noto 등 잔존 | 자동 |
| **4. 그림자** | 9 | 정의된 그림자 사용 | 임의 그림자 | 자동 |

### 제외한 것과 이유
- **간격(spacing)·반경(radius)**: 값은 정의돼 있으나 "언제 무엇을 쓴다"는 기준이 없어 판정 근거가 없다.
  → 나중에 되살리는 법: 질문을 **"정의된 값 중 하나인가"** 로만 좁히면 판정 가능(5px·13px 같은 임의값만 잡고, 8이냐 12냐는 묻지 않음). **2차 편입 후보.**
- **명도대비 등 접근성 항목**: 1차 범위 밖.
- **Figma 위생 항목**(레이어 이름·오토레이아웃·숨김 레이어·빈 프레임·이미지 텍스트 등): 판정은 쉬우나 1차에서는 제외 — 체크리스트를 토큰·스타일 준수로 한정. **재검토 후보로 보존.**
- **화면 네이밍·기준 해상도**: 네이밍 정책은 신규 작성 패턴에만 적용되므로 검수기 항목으로 부적합.

### 항목 간 관계 (중복이지만 둘 다 유지)
- 5번(text style 적용)을 통과하면 6·8번은 자동 충족된다. 6·8번은 **style이 없는 텍스트를 잡는 안전망**이다.
- 8번(Pretendard)은 프로젝트 하드룰(H3)이라 별도 항목으로 보이는 것이 낫다.

## 3. 2번 항목 — foundation 사용의 3단계 (융통성)

구조가 아직 덜 잡혀 foundation을 직접 써야 하는 경우가 있으므로 **막지 않는다.**

| 사용 | 판정 | 동작 |
|---|---|---|
| semantic 사용 | ✅ | — |
| **foundation 직접 사용** | ⚠️ **허용, 기록만** | 값이 같은 semantic이 있으면 치환 제안 / 없으면 **semantic 신설 후보로 수집** |
| 하드코딩 | ❌ | 자동 치환 |

효과: foundation 사용을 막지 않으면서 **어떤 semantic이 부족한지가 자동으로 쌓인다.** 검수기가 구조 정리의 근거를 만들어준다.

## 4. 자동 변경 정책

자동 변경의 성립 조건은 하나 — **`발견된 값 → 정본 값` 매핑이 유일한가.**

| 상황 | 동작 |
|---|---|
| 정답이 하나 | 자동 변경 |
| 후보가 여러 개 | 후보 제시 후 사용자 선택 |
| 대응하는 정본 없음 | 고치지 않고 **신설 후보로 수집** |

### 확정된 3가지 결정 (HD 답변)

- **HD-1 — 같은 색인데 semantic 후보가 여러 개일 때** → **컴포넌트 치환으로 해소한다.**
  속성별 치환 우선순위 규칙을 만드는 대신, 컴포넌트로 구분 가능한 것은 컴포넌트 자체로 교체해 semantic 선택 고민을 없앤다. (= 2차의 컴포넌트 항목 일부를 1차로 선도입)
- **HD-2 — 정의에 없는 폰트 크기** → **전체 자동 변경하지 않는다.** 화면에서 후보(예: 15px → 14 / 16 / 그대로)를 제안하고 **사용자가 항목별로 선택**한다.
- **HD-3 — text style 매칭 허용 범위** → **(A) 크기·굵기가 일치하면 같은 것으로 보고 style을 입힌다.** 행간은 정본 값으로 정리된다.

### 컴포넌트 판별의 한계 (정직하게 명시)
컴포넌트 판별은 토큰 판별보다 어렵다. "이 레이어 뭉치가 Button이다"를 크기·구조·텍스트 스타일로 추정하므로,
- **확신 높음**(크기·구조·값이 정본 variant와 일치) → 체크 기본값 ON
- **확신 낮음**(크기만 일치 등) → 체크 해제 상태로 표시, 자동 실행 대상에서 제외
- 교체 시 **입력해 둔 문구(텍스트 오버라이드)는 유지**한다.

### 안전장치
- **한 번의 자동 변경 = 되돌리기 한 번**으로 묶는다 (Figma plugin 실행을 단일 undo 스텝으로).
- 무엇을 바꿨는지 **변경 목록**을 함께 낸다.
- 고치는 버튼은 **항상 목록을 확인한 뒤** 실행된다. "한 번에 고치기"도 목록 확인 단계를 거친다.

## 5. 검수기 화면 — 텍스트 와이어프레임

Figma 플러그인 패널(좁은 세로 폭) 기준.

### 5-0. 실사용 반영 운영 순서 (2026-09-01)

1. **설치 우선**: Foundation·Semantic·Text Styles·Component Set이 모두 있어야 검사를 시작한다. 빠진 항목이 있으면 검사 버튼을 잠그고 설치 탭의 전체 선택으로 연결한다.
2. **컴포넌트 우선**: 첫 검사는 컴포넌트만 판정한다. 교체 후보가 남아 있으면 색·텍스트·그림자 결과는 열지 않는다.
3. **재검사로 다음 단계 이동**: 컴포넌트 교체 또는 모듈 구조 확인 뒤 같은 최초 선택 범위를 다시 검사한다. 교체 후보가 정리된 경우에만 나머지 항목을 검사한다.
4. **의미 단위 집계**: 아이콘의 개별 vector/path, 버튼의 배경·라벨·아이콘을 각각 한 건으로 세지 않는다. 가장 가까운 아이콘·버튼·인스턴스 단위로 묶고, 같은 위반을 가진 내부 paint는 한 번의 적용으로 함께 고친다.
5. **모듈 구조 우선 판정**: `m_button` 같은 이름을 예외 목록에 넣지 않는다. 바깥 인스턴스 안에 같은 최신 부품으로 해석되는 자식이 2개 이상 있으면 여러 부품의 묶음으로 판정해, 바깥 묶음을 최신 부품 하나로 축소하지 않는다.
6. **이름 불일치 항목 선택**: 같은 레거시 원본을 여러 번 쓴 경우에도 배치된 인스턴스별로 카드를 표시한다. 카드 제목·현재 정보 영역을 누르면 해당 인스턴스를 Figma에서 선택하고, 드롭다운은 방해하지 않는다.
7. **항목별 되돌리기**: 교체 직전 인스턴스를 숨은 임시 복사본으로 보관한다. 교체 뒤 버튼은 짧은 `되돌리기`로 바뀌며, 누르면 컴포넌트 연결뿐 아니라 내부 override를 포함한 복사본 전체를 원래 부모·순서·위치에 복원한다. 상세 재검사 뒤에도 최근 교체 카드에서 되돌릴 수 있고, 새 검사·플러그인 종료 때 남은 임시 복사본을 정리한다.

선택 범위는 플러그인 안에서 다시 고르지 않는다. Figma 캔버스에서 부분 선택하면 선택한 요소만, `Cmd/Ctrl+A`로 전체 선택하면 페이지의 선택된 전체 요소를 검사한다. 선택이 없으면 검사 시작 버튼은 비활성이다.

### (2) 검사 중 — 체크리스트 + 진행률

```
┌────────────────────────────────────┐
│ 검사 중                            │
│ 로그인 화면 외 2개 · 노드 124개   │
│ ███████████████░░░░░░       60%   │
├────────────────────────────────────┤
│ ✓ 최신 컴포넌트 사용               │
│ ✓ 가이드에 등록된 색상 사용        │
│ ✓ 용도에 맞는 가이드 색상 사용     │
│ ◌ 가이드 색상·글자 스타일 확인 중…│
│ ○ 가이드에 정의된 투명도 사용      │
│ ○ 가이드 글자 스타일 사용          │
│ ○ 가이드에 정의된 글자 크기 사용   │
│ ○ 가이드 글자 스타일 값 그대로 사용│
```

- 대기 `○` → 검사 중 `◌` → 완료 `✓` 순서로 바뀐다.
- 엔진이 아직 판정하지 못하는 항목은 완료 체크 대신 `— 미판정`으로 남긴다.
- 검사 중에는 중복 실행을 막기 위해 검사 시작 버튼과 선택 적용 동작을 잠근다.

### (4) 컴포넌트 치환 (1단계)

## 6. 화면 설계 원칙 3가지

1. **요약 화면의 항목 목록이 곧 판정 범위** — 리스트에 없는 것은 검수기가 보지 않는다는 뜻이 저절로 전달된다. 커버리지를 따로 설명할 필요가 없다.
2. **고치는 버튼은 항상 목록을 본 뒤에** — "한 번에 고치기"도 누르면 목록 확인 단계를 거친다. 모르고 바뀌는 일이 없어야 계속 쓴다.
3. **막다른 길을 만들지 않는다** — 대응 정본이 없으면 언제나 `신설 후보로 보내기`가 붙는다. "이건 어쩌라고?"로 끝나는 지점이 없어야 한다.

또한 항목별 결과는 **pass/fail만 표시하지 않고 반드시 건수(위반 수 / 전체)와 위치 목록을 함께** 낸다. pass/fail만 있으면 1건 위반과 100건 위반이 똑같이 ❌로 보여 고칠 우선순위가 나오지 않는다.
