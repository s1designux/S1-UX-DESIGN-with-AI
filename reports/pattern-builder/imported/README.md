> river 요청 2026-09-18: "피그마로 만든 기존 화면을 빌더에 연결하면 그 화면을 빌더가 자동으로 조합해주는
> 기능이 있으면 좋겠어. 보통 모두앱 추가 개발할 때는 기존 화면에서 기능 추가하는 경우가 많거든."
>
> river 결정 2026-09-18: **"모두앱에서는 레거시 모습 그대로 가져와야 해. 다른 서비스에서는 규칙이 다르니 참고해."**

## 무엇을 하나

원본 화면을 **위에서 아래로 칸 단위로 잘라** 빌더 캔버스에 그대로 올린다.
그 사이·그 아래에 정본 부품을 끼워 넣으면 「기존 화면 + 새 기능」이 된다.

## 가져오는 규칙은 묶음마다 다르다

`profiles/<매체>-<서비스>/profile.json` 의 `import.mode` 가 정한다. **정하지 않으면 가져오기가 멈춘다**(임의 판단 금지).

| mode | 무엇을 하나 | 지금 쓰는 묶음 |
|---|---|---|
| `legacy-as-is` | 칸마다 **원본 그림을 그대로** 올린다. 대응이 정해진 이름이라도 **바꿔치기하지 않는다** | `app-modu`(모두앱) |
| `canon-swap` | 대응이 정해진 칸을 정본 부품으로 갈아 끼운다 | 아직 없음 — 무엇을 어떻게 바꿀지가 결정되지 않았다(needs-decision) |

## 쓰는 법

```
npm run pattern:order  -- <service> --from-raw          화면마다 "위→아래 차례" 를 뽑아 둔다(한 번)
npm run pattern:import -- <profile> --find "홈"          가져올 화면 찾기
npm run pattern:import -- <profile> --screen 23065:17941 그 화면 가져오기
```

가져오면 빌더 왼쪽 「가져온 화면」 탭에 뜬다. 누르면 캔버스에 올라간다.

## 올릴 때 빌더가 하는 것

- 플랫폼을 원본 폭에 맞춘다(360 이하면 모바일).
- **기기 크롬을 「없음」으로 시작한다** — 원본에 상태바·내비가 이미 들어 있어 겹치기 때문.
- 줄 사이 간격은 원본 px 그대로 쓴다(토큰 눈금으로 반올림하지 않는다).
- 원본 본문이 좌우 어디서 시작하는지 재서(`importedInset`), **새로 놓는 정본 부품을 그 자리에 맞춘다.**

## 지키는 선

- **레거시 칸은 우리 부품이 아니다.** 캔버스에서 점선으로 표시하고, 속성 칸에 "바꿀 수 있는 값이 없다"고 적는다.
- 속성 칸의 「원본에 쓰인 이름」은 **참고 표시**다. 「정해짐」이라도 자동으로 바꾸지 않는다.
- 이름 대응은 **결정표에 있는 것만** 적는다 — 없으면 「아직 안 정함」·「모름」이라고 적고 지어내지 않는다(H6②).
- 가져온 화면은 레거시 묶음 안에만 쌓인다. **정본 패턴 목록(`catalog.json`)에 넣지 않는다.**
- 내보낸 HTML 의 레거시 칸은 **원본을 찍은 그림**(data URI)이다. 파일 맨 위 주석이 몇 개인지 알려 준다.

## 되풀이되는 차례 찾기 (🖥️ 로컬 모델)

```
npm run pattern:similar -- <service> --cluster --by order
```

화면 이름을 빼고 **차례만** 벡터로 바꿔 닮은 것끼리 묶는다. 결과는 `inventory/<service>/order-clusters.md`.
모두앱 1004장 → 묶음 219개, 24초, 클라우드 토큰 0. **후보일 뿐이고 판정은 사람이 한다.**
