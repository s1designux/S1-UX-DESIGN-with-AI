# 화면 상태 규칙

> 묶음 `app-modu`(휴대폰 앱 · 모두앱) 전용 — 정본에 합치지 않는다. 배경은 [README.md](README.md)
> 상태 표기: 확정 / 관찰 / 미작성
> `관찰` 항목의 근거는 MoDU APP 레거시 화면 1084장 판독.

## 모든 화면이 가져야 하는 상태

- 미작성 · 어느 상태까지를 필수로 볼지는 아직 근거가 없다. 아래 각 상태의 관찰만 먼저 적는다.

## 비어 있음(데이터 없음)

- 관찰 · **가장 많이 그려진 상태다**(85장, 10개 영역 모두에 존재). 목록·검색·신청내역 어디에나 빈 상태 화면이 따로 있다.
- 관찰 · 빈 상태에서도 머리와 하단 탭바는 그대로 둔다(84/85장).
- 관찰 · 빈 상태에 하단 버튼을 두는 경우는 일부다(23/85장) — 할 일이 있을 때만 둔다.

## 기다리는 중(로딩)

- 관찰 · 두 가지로 나뉜다 — **짧은 로딩**과 **긴 로딩**(안내 문구를 함께 보여준다).

## 잘못됨(오류·통신 실패)

- 관찰 · 화면 전체를 덮는 오류 화면이 따로 있다(18장). 머리·탭바 없이 안내와 다시 시도만 둔다.

## 권한이 없을 때

- 관찰 · **권한 없음이 하나의 화면 상태로 따로 있다**(17장, 4개 영역). 관리자 등급·계약 유무·서비스 미개시로 갈래가 나뉜다.

## 상태끼리 섞이지 않게 하는 규칙

- 관찰 · 한 화면 이름에 상태를 하나만 붙인다. 두 상태가 겹치면 화면을 따로 그렸다.
