# MoDU APP — 되풀이되는 화면 갈래와 우리 부품 대응

> 판독한 화면 547장을 생김새로 묶은 결과다. 묶는 기준은 이름의 상태 낱말과 실제로 쓰인 부품 구성이다.
> 이 표는 **관찰**이고, 무엇을 패턴으로 만들지는 river 가 정한다.

## 패턴으로 먼저 만들 만한 것 (많이 쓰이고 서비스를 안 가림)

1. **목록 화면** — 43장, 9개 영역. 빈 상태(60장)와 짝을 이룬다.
2. **입력 폼 화면** — 27장. 키보드 상태(36장)가 딸린다.
3. **선택 목록 화면** — 20장. 체크/라디오만 다르고 뼈대는 목록과 같다.
4. **설정 목록 화면** — 9장. 목록 뼈대에 토글을 붙인 것.
5. **약관·동의 화면** — 17장.

## 우리에게 아직 없는 것 (needs-decision)

| 없는 것 | 레거시 쓰임 | 왜 필요한가 |
|---|---|---|
| **목록 한 줄** | 화살표 335 · 구분선 250 · 줄 241 | 목록·선택·설정 세 갈래 패턴이 전부 이 줄 위에 선다. 가장 급하다 |
| **빈 상태 안내 덩어리** | 60장 | 그림 + 한 줄 안내 + (선택) 버튼 |
| **홈형 머리(햄버거+알림)** | 101장 | 서브형 머리와 다른 형태 |
| **전면 오류 화면** | 7장 | 머리·탭바 없이 안내만 |
| **로딩·토스트** | 4장 | 겹쳐 뜨는 알림 |

상태표시줄과 키보드는 휴대폰 운영체제가 그리는 것이라 우리 부품으로 만들지 않는다.
