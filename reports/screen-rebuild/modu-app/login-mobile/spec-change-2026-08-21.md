## 추가 결정 — 에스원 CI 크기 정정 (같은 날, river님 결정)

### 진단

### 결정: 42×16 → **78.75×30** (river님, 2026-08-21)

- 위 **2026-06-23 결정과 로그인 재현 허용편차(78×30→42×16)를 함께 철회**한다.
- 지시값은 77.86×30 이었으나 **78.75×30** 으로 확정: 로고 벡터의 viewBox 가 `0 0 42 16`(비율 2.625)이라 77.86×30(비율 2.595)을 그대로 쓰면 워드마크가 세로로 ~1% 눌린다. 78.75×30 = 42×16 의 **정확히 1.875배**로 비율 보존·왜곡 0이며 높이 30 은 지시대로다.
- 원본 자산(77.86×30)과 정본 벡터(2.625 비율)의 미세한 비율 차이는 자산이 서로 다른 데서 온 것으로 보이며, 이번 범위에서는 벡터 왜곡을 만들지 않는 쪽을 택했다.

`S1_LOGO_SVG` 공유 상수는 **고치지 않았다**(Footer 로고가 같은 상수를 42×16 으로 사용). `buildCI` 안에서 svg 의 `width`/`height` 만 78.75/30 으로 치환해 viewBox 기준 비례 확대하고, 치환이 no-op 되면(상수 표기 변경 시) 로고가 42×16 으로 남는 조용한 결함이 되므로 **즉시 throw 하는 방어선**을 추가했다.

## 결함 수정 — 모달 버튼 아래 여백 과다 (같은 날, river님 신고)

### 신고
자동 로그인 선택 A(`1562:9`)·B(`1562:10`) 팝업의 **버튼 아래 공간이 정본보다 크다**. "처음 만들어졌을 때는 문제 없었는데 중간에 이상하게 수정됐다."

### 원인 — 재현 중 걸어둔 `minHeight: 208` 강제

`3-build.md` 기록: *"긴 문구가 잘리는 문제를 발견 → 메시지를 `textAutoResize=HEIGHT`, 모달을 `HUG + minHeight 208`로 설정"*. 이 `minHeight` 가 **문구가 짧은 두 화면에서만** 남는 공간을 만들었다.

| 화면 | 실제 높이 | 내용에 맞는 높이 | 초과 | 버튼 아래 여백 |
|---|---|---|---|---|
| `1562:9` 자동 로그인 A | 208 | **187** | **+21** | **41px** |
| `1562:10` 자동 로그인 B | 208 | **187** | **+21** | **41px** |
| `1562:11` 새 기기 A | 229 | 229 | 0 | 20px |
| `1562:12` 새 기기 B | 208 | 208 | 0 | 20px |
| `1562:13` 새 기기 C | 250 | 250 | 0 | 20px |

정본 `Modal`(`Break=Mobile, Footer=Single` `1610:6729` / `Footer=Dual` `1611:6731`)은 **`minHeight` 없음 · HUG** 이고, 자연 높이가 정확히 208(pad 20 + content 90 + gap 30 + footer 48 + pad 20)이다. 즉 208 은 "최소값"이 아니라 "정본 문구(2줄) 기준의 결과값"이었는데, 그것을 최소 높이로 굳힌 것이 오류다.

### 조치 (파생을 정본에 맞춤)

모달 인스턴스 **5개 전부**의 `minHeight` override 제거 → 정본과 동일하게 내용에 맞춰 HUG.

| 노드 | 화면 | 높이 | 버튼 아래 여백 |
|---|---|---|---|
| `1566:468` | 자동 로그인 A | 208 → **187** | 41 → **20** |
| `1566:554` | 자동 로그인 B | 208 → **187** | 41 → **20** |
| `1566:638` | 새 기기 A | 229 → 229 (불변) | 20 (불변) |
| `1566:722` | 새 기기 B | 208 → 208 (불변) | 20 (불변) |
| `1567:723` | 새 기기 C | 250 → 250 (불변) | 20 (불변) |

- 긴 문구 모달 3개는 **높이가 전혀 변하지 않았다** → 잘림 방어는 `minHeight` 가 아니라 `textAutoResize=HEIGHT` + 모달 `HUG` 가 하고 있었음이 실증됐다(회귀 0).
- 모달은 오버레이 세로 중앙정렬이라 y 는 자동 재계산(263.5 → 274). 수동 위치 조정 없음.
- 렌더 육안 확인: 두 화면 모두 버튼 아래 여백이 좌우·상단 여백과 균등.

### 재발 방지

`canonical-manifest.json` → `internalContracts.ModalLongMessage.modalMinHeight` **208 → null** 로 폐기하고 이유를 주석으로 박았다. 이 계약서를 보고 재현하는 다음 작업이 같은 실수를 반복하지 않게 한다.

> ⚠️ 이 폴더의 기존 기록물(`node-map.json` `modalSizes`/`modalMinHeight`, `scan-summary.json` `modalHeights [208,208,229,208,250]`)은 수정 이전 시점 값이다. 현재 값은 `[187,187,229,208,250]`.

### 남은 관찰 (조치 안 함)

`1562:10`(자동 로그인 B) 모달의 `message` 텍스트 레이어가 **빈 문자열**인데도 21px 높이 + 앞 간격 24px 을 차지한다(제목만 있는 모달). 시각적으로는 제목 아래 여백으로 보여 부자연스럽지 않아 그대로 뒀다. 없애려면 별건으로 판단 필요.
