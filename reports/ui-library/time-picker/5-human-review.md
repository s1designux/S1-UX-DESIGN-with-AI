## 1차 검수 — 지시 3건

| # | river 지시 (원문) | 결과 |
|---|---|---|
| R-1 | "pc에서도 액션에서 24시간/오전오후제를 구분해서 보여주면 좋겠어" | Action 실물 줄을 `24시간제`·`오전·오후` 두 줄로 분리 |
| R-2 | "pc, 모바일 모두 인풋의 디폴트 width값이 너무 좁아 좀더 넓혀줄래" | 트리거 최소 폭 78 → **정본 150px** |
| R-3 | "filled 됐을때 인풋 크기가 작아지는데 수정해줄래" | R-2 와 같은 원인(폭이 글자 길이를 따라감) — 함께 해소. 5상태 전부 150px |

R-2·R-3 의 뿌리는 `registry/components/time-picker.json` 의 `sizing.minWidth: 78px` 이었고, **그 값은 정본 어디에도 없는 레거시 손관리 CSS 유래**였다(독립 검증 3회차에서 확인 후 정본 150 으로 정정).

## 2차 검수 — 목록 폭

river 질문: **"현재 드롭다운이 인풋보다 더 작거나 더 크게 표출되는데 이걸 인풋에 맞출 수 있을까?"**

실측을 보여주고 결정을 받았다.

| | 지금 | 150 으로 줄이면 |
|---|---|---|
| "오전" 글자 실폭 | 24.2px | — |
| 칸 좌우 여백(정본) | 12 + 12 = 24px | **4.56px 로 무너짐** |
| 한 칸에 필요한 폭 | 48.2px | 열 33.33px |
| 정본 12h 칸 | **48px — 이미 한계치** | — |

river 결정: **"24시간만 인풋에 맞춰줘  12시간제는 현재 유지"**
→ 패널에 `min-width: 100%` — 24h 는 121→150(입력칸과 동일), 12h 는 194 유지.

> **정정 기록:** ⭐ 가 처음 "150 이면 글자가 구분선을 뚫는다"고 설명했으나 4회차 독립 검증의 통제 실험 결과 **글자는 열 안에 남고 여백만 무너진다.** 결정을 떠받친 숫자는 정확했고 결정은 유효하나, 설명이 과장이었다. 기록 3곳을 정정했다.

## 이번 검수에서 river 가 잡은 것 (기계·AI 가 못 잡은 것)

세 지시 모두 **검사기도 독립 검증도 통과한 상태**에서 나왔다.
- 폭이 좁은 것·Filled 에서 줄어드는 것은 값이 계약대로였기 때문에(78px 이 registry 에 선언돼 있었다) 기계가 위반으로 보지 않았다.
- 목록이 입력칸과 어긋나는 것은 정본이 실제로 그렇게 생겼기 때문에 원본 대조로는 잡히지 않았다.

**「정본대로인데 쓰기 불편한 것」은 사람만 잡는다** — 이 작업의 5단계가 실제로 값을 한 지점이다.
