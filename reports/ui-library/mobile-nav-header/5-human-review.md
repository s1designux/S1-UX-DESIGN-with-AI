## 검수 후 발견해 고친 것 (F-5)

이 4건을 🤖 component-verifier 가 승격 직전에 독립 검증하면서 **실제 결함 1건**을 잡았다.

- **증상:** 목업 상태바의 wifi 가 호 2겹이 아니라 **속이 꽉 찬 부채꼴**로 그려졌다. 신호·배터리·글자는 정상.
- **원인:** wifi SVG 의 마스크 `id` 가 고정 문자열이라 한 페이지에 여러 번 그려지며 중복됐고, `url(#...)` 이 문서 순서상 첫 번째(= 숨겨진 PC 블록 안)를 가리켜 마스크가 적용되지 않았다. **숨겨진(display:none) 요소 안의 마스크는 적용되지 않는다.**
- **왜 위 검증을 통과했나:** 위 "중복 id 0건" 은 라디오만 보고 페이지 전체로 일반화한 문장이었다(실제로는 SVG 마스크 id 8개가 중복). 수치 대조도 전부 맞았다 — **수치는 맞는데 그림이 틀린** 경우였다.
- **고침:** 마스크 id 를 인스턴스마다 새로 만들고, 하단 탭 목업도 PC·Mobile 블록마다 새로 생성한다(같은 문자열 재사용이 중복의 원인이었다).
- **확인:** 페이지 전체 중복 id **0건** · wifi 4개 모두 자기 SVG 안의 마스크를 참조 · 실제 화면 SVG 를 캔버스로 재현해 픽셀 확인(바깥 호 채워짐 · 호 사이 빈 공간 alpha 0 · 안쪽 호 채워짐 · 점 채워짐).

## 정직하게 남기는 것

- 위 4건은 **배포 부품(dist)을 바꾸지 않았다** — 안내 화면 코드(`assets/js/ui-library-guide.js` · `assets/css/ui-library-guide.css`)만 바뀌었다.
- 4건의 검증은 처음에 **⭐ 자가인증**이었고, 그 자가인증이 F-5 를 놓쳤다. 승격 직전 🤖 component-verifier 4회차가 잡았다 — 화면 수정도 자가인증만으로 닫으면 안 된다는 사례로 남긴다. 배포 부품에 대한 독립 검증은 2·3회차(4-verification)에 있다.
- 상태바는 여전히 **웹 배포본에 없다**(D5). 안내 화면 안의 그림일 뿐이고 실제 서비스에서는 OS·브라우저가 그린다. 정본 Web 변형(주소창 포함 77px)은 목업이 앱 화면이라 옮기지 않았다.
