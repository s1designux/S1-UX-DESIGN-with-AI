# 2-canon-readiness — Mobile Bottom Nav · Mobile Header

- 작업: mobile-nav-header · 날짜: 2026-09-02 · 계약 `ui-library-code-contract.json` v0.1.2 (candidate)
- 결론: **검문소 미통과 — needs-decision 2건 + 준비물 1건.** river 결정 전 3-build 착수하지 않는다.

## A. 준비된 것

| 항목 | 상태 |
|---|---|
| 시각 정본 | 두 컴포넌트 모두 축·수치·토큰 확정 |

## B. 막는 것 — needs-decision

### HD-1. 두 컴포넌트의 접근성 규칙을 이번에 확정할까요?
- **무엇:** 하단 탭은 "지금 어느 탭에 있는지"를 화면낭독기에 알리는 것, 헤더는 이전·닫기·알림 버튼에 이름을 주는 것.
- **왜:** 등록부에 문장은 있는데 **등급이 "미정(pending)"** 이라 계약상 승인 배포가 막힙니다. 모달 때와 같은 상황입니다.
- **선택지:** **(A)** 모달과 같은 표준 수준으로 확정 — 탭 목록 표시(`role=tablist`/`tab`/`aria-selected`) · 아이콘 버튼에 이름 · 제목 없는 헤더에서 heading 구조 유지 · 터치 영역 최소 44 확보. **(B)** 더 넓게(탭 화살표 키 이동·헤더 landmark 규칙까지).
- **안 정하면:** 만들어도 승인 배포가 막힙니다.

### HD-2. 헤더의 "상태바"(시간·배터리·주소창)를 웹 배포본에 넣을까요?
- **무엇:** 정본 헤더는 위에 **상태바**가 붙어 있습니다. App 은 시간·배터리 줄(27px), Web 은 거기에 **브라우저 주소창**까지(77px). 그래서 헤더 전체 높이가 99 / 149 입니다.
- **왜 결정이 필요한가:** 실제 서비스에서 이 부분은 **우리가 그리는 게 아니라 휴대폰 OS와 브라우저가 그립니다.** 정본에 있다고 그대로 웹으로 내면, 개발자가 가짜 상태바를 화면에 그려 넣는 일이 생길 수 있습니다.
- **선택지:**
  - **(A) 상태바 빼고 헤더 막대(56px)만 배포** — 실제 코드에 필요한 것만 냅니다. 안내 화면에는 "위에 상태바가 온다"를 그림으로만 보여줍니다. 정본의 12변형은 상태바를 뺀 6변형(Type)으로 줄어듭니다.
  - **(B) 정본대로 상태바까지 포함해 12변형 배포** — Figma 와 1:1이지만, 쓰지 않을 코드가 배포본에 들어갑니다.
- **안 정하면:** (A)로 갑니다.

## D. river 결정 없이 확정되는 것 (내가 정함)

| 항목 | 이번 배포에서 |
|---|---|
| 하단 탭 "바" | **아이템 1칸만 배포**한다. 정본·등록부 둘 다 "바는 컴포넌트가 아니다"라고 명시했다. 안내 화면에는 4칸으로 조립한 예시와 배경색(`--color-navigation-bg`) 안내를 함께 싣는다 |

| 하단 탭 상태 | unselected · selected 2가지만. hover·disabled 는 정본에 없어 만들지 않는다 |
| 헤더 유형 | Type 6종 전부. 원본에서 삭제된 "Home / Title + 2 Icons" 는 만들지 않는다 |

| 헤더 좌측 여백 | Home 20 / Standard 16 (정본 그대로) |
| 안내 페이지 분류 | 등록부대로 **Navigation** 분류. 헤더는 사이트에 화면이 없어 새로 만든다 |
