## B. 막는 것 — needs-decision

### HD-1. 표 헤더의 "정렬(소트)" 기능을 이번 배포에 넣을까요?
- 무엇: 열 제목 옆 화살표를 눌러 오름차순·내림차순으로 바꾸는 기능.
- 왜 결정이 필요한가: **정본(설치기)에는 정렬 아이콘 자체가 없습니다.** Registry 설명글에만 "combobox_arrow 18×18" 이라 적혀 있고, 지금 사이트 화면은 어디에도 없는 자체 그림(10×14)을 쓰고 있습니다. 계약상 허용목록 밖 아이콘을 임의 SVG 로 확정할 수 없습니다.
- 선택지: **(A)** 이번엔 정렬 없이 배포(표·선택·행 상태만) · **(B)** 정렬을 넣기로 하고 아이콘을 먼저 정본(설치기)에 추가한 뒤 배포.
- 안 정하면: (A)로 갑니다 — 정렬 아이콘 없는 표가 나가고, 접근성의 `aria-sort` 항목도 이번 범위에서 빠집니다.

### HD-2. 표 아래 "페이지 번호 + 몇 개씩 보기"를 표 배포본에 포함할까요?
- 무엇: 정본 Figma 의 Table 은 표 안에 페이지네이션 바와 작은 셀렉트가 붙은 통짜 부품입니다.
- 왜: 통짜로 내면 쓰기는 쉬운데 화면마다 다른 페이지 규칙을 못 바꿉니다. 표만 내면 화면에서 표+페이지네이션을 조립해야 합니다.
- 선택지: **(A)** 표만 배포하고 페이지네이션은 이미 만든 부품을 화면에서 조립(권장 — 이미 Pagination 을 따로 배포 중) · **(B)** 정본대로 푸터까지 포함한 통짜 Table 배포.
- 안 정하면: (A)로 갑니다. 안내 페이지에는 "표 + 페이지네이션 조립 예시"를 함께 싣습니다.

### HD-3. 열 정렬(가운데/왼쪽)을 공식 옵션으로 열까요?
- 무엇: 수량·관리 같은 열을 가운데 정렬로 두는 옵션.
- 왜: 정본 코드에는 **왼쪽 정렬 하나뿐**인데, Registry 문서와 지금 사이트 화면에는 가운데 정렬이 섞여 있습니다. 규칙을 제가 임의로 만들 수 없습니다.
- 선택지: **(A)** 왼쪽 정렬만 배포(정본 그대로) · **(B)** `data-align="center"` 를 공식 옵션으로 추가하고 정본에도 반영.
- 안 정하면: (A)로 갑니다 — 지금 사이트의 가운데 정렬 열들은 왼쪽으로 바뀝니다.

### HD-4. 표 접근성 등급이 "미정(pending)" 이라 이대로는 배포 승인이 안 됩니다.
- 무엇: 표는 헤더 표시(th·scope), 전체선택 체크박스의 이름, 키보드 이동 규칙이 정해져야 합니다. 지금 행동 장부에는 선택 동작만 있고 키보드·포커스·접근성은 "미정"입니다.
- 왜: 계약이 "접근성 미정인 컴포넌트는 approved 배포 불가"로 못박고 있습니다.
- 선택지: **(A)** 다른 승인 컴포넌트와 같은 수준(네이티브 표 시맨틱 + 전체선택 라벨 + 각 행 체크박스 라벨)으로 이번에 확정 · **(B)** 정렬·키보드 이동까지 포함한 확장 접근성을 목표로 잡고 범위를 키움.
- 안 정하면: 표는 만들어도 **승인 배포가 막힙니다.**
