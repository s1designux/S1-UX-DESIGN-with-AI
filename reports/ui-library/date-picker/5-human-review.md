## 2. 봐 주셨으면 하는 것 (UX 관점)

1. **날짜를 고르는 흐름이 자연스러운가** — 트리거를 누르고, 달을 넘기고, 날짜를 고르고, 값이 들어오는 과정.
2. **연도·월로 가는 길이 알기 쉬운가** — 지금은 달력 위의 「2025년」 「1월」 글자를 각각 누르면 그 화면으로 갑니다. 버튼처럼 안 보여서 못 찾을 수 있습니다.
3. **기간 선택이 이해되는가** — 시작일을 고른 뒤 마우스를 움직이면 끝날 자리까지 연한 띠가 미리 칠해집니다. 잘못 골랐을 때 되돌리는 방법이 자연스러운지(시작일보다 앞선 날짜를 누르면 그 날짜가 새 시작일이 됩니다).
4. **모바일 시트가 손에 맞는가** — 시트 높이, 「적용」 버튼 위치, 닫는 방법(배경 탭·X·Esc).
5. **정보와 행동의 우선순위** — 오늘 날짜와 선택한 날짜의 구분이 충분한가(오늘=테두리 원, 선택=꽉 찬 원).

## 3. 함께 봐 주셔야 하는 것 — 시간 휠 시트

타임피커의 **모바일 시간 휠 바텀시트**를 이번에 함께 만들었습니다(지난 작업에서 "데이트피커 때 같이 만들자"로 미뤄둔 것).

⚠️ **검수 화면이 컴포넌트 단위로 승인 상태를 읽기 때문에, 타임피커는 이미 승인돼 「승인 완료(참고)」 탭에 있습니다.** 그래서 이 시트가 river 님 검수 대상에서 자동으로 빠집니다 — 독립 검증이 지적한 문제(C-6)라 여기에 명시적으로 적습니다.

보는 법: 안내 페이지 모바일 화면의 Time Picker 섹션, 또는 스크린샷 `screens/mobile-wheel-timeonly.png` · `screens/mobile-wheel-datetime.png`.

## 4. river 님 결정이 필요한 것

### HD-1. 달력에서 일요일을 빨강, 토요일을 파랑으로 칠할까요?

- **지금 웹은 칠하고 있습니다**(보내드린 화면 그대로).
- 색 자체는 정본에 `일요일용 빨강`·`토요일용 파랑`이라는 **이름으로 이미 존재**합니다. 새로 만든 색이 아닙니다.
- 그런데 **Figma 쪽 달력은 요일을 전부 같은 색**으로 칠합니다. 그리고 사이트 코드(`pages/components.html:881`)에 이런 과거 결정 주석이 남아 있습니다 — **"주말 특별색 없음(사용자 결정 D — 경비업)"**. 경비업이라 주말·평일 구분이 의미 없다는 취지로 보입니다.
- (A) 과거 결정대로 **주말 색을 빼고** 전부 같은 색 / (B) **지금처럼 주말 색 유지**(과거 결정을 바꾸는 것)
- **안 정하시면**: 지금처럼 주말 색을 유지하고, Figma 를 나중에 맞추는 것으로 기록해 둡니다.

### HD-2. 연도·월로 가는 방법을 지금처럼 둘까요?

- river 님이 "연도·월 버튼을 따로 둘 다"를 고르셨고, **정본에 없는 버튼 모양을 새로 만들지 않기 위해** 기존 헤더 글자(24px Bold)를 「2025년」「1월」 둘로 쪼개 각각 누를 수 있게 했습니다.
- 화면에서 보시고 **버튼처럼 안 보여 못 찾겠다**면 말씀해 주세요. 그때는 정본에 부품을 새로 만드는 결정이 필요합니다.

### HD-3. 승인 문장 — river 님이 직접 타이핑해 주셔야 합니다

새 컴포넌트가 만드는 상태 이름 5개(`date-picker` 의 default·filled·open·hover·disabled)를 정본 감시 장치(Gate 34)가 막고 있습니다. **선택지 클릭은 승인 근거로 인정하지 않도록** 만들어 둔 장치라(2026-09-03 river 지시), river 님이 문장을 **직접 입력**해 주셔야 통과합니다.

예시: **「데이트피커 웹 배포본 승인할게. 상태 5개 신설 승인.」**

문장은 river 님 말씀대로 하셔도 됩니다 — 제가 그 문장을 그대로 인용해 기록합니다.
