## 7. 상태 플래그에 대한 정직 표기

두 컴포넌트 manifest 의 `status` 를 `draft` → `verified` 로 올린 것은 **⭐ 가 했다.** 이유는 안내 화면(`pages/components.html`)의 `mountGuide` 가 `verified`·`approved` 만 그리기 때문에, 그 화면을 **독립 검증자와 river 가 볼 수 있게** 하려면 먼저 올려야 했기 때문이다.

즉 이 플래그는 **판정이 아니라 화면을 여는 스위치**다. 독립 검증이 ❌ 를 내면 `draft` 로 되돌린다.

## ❌(a)-1 배경 스크롤 잠금이 모달과 어긋남 — **고침**

**증상(재현율 100%):** 시트를 열고 그 위에 모달을 연 뒤 시트만 닫으면 **모달이 열려 있는데 배경이 풀린다.** 이어서 모달을 닫으면 **아무것도 안 열렸는데 페이지가 잠긴 채 남는다**(새로고침 말고는 못 빠져나온다).

**원인:** `bottom-sheet.js` 와 `modal.js` 가 **같은 자리**(`body` 인라인 `overflow`)를 각자 저장·복원한다. 별도 모듈이라 서로의 카운터가 보이지 않아 저장값을 덮어쓴다.
게다가 manifest `scrollLockNote` 에 "열린 시트**(+모달)** 수를 세어"라고 적어 **코드가 하지 않는 일을 주장**하고 있었다. modal·modal-content 는 자기 범위만 적었는데 이번 것만 범위를 넓혀 적은, 이 작업이 새로 넣은 거짓 주장이다.

**고친 방법:** 잠그는 **자리를 나눈다.** modal 계열은 `body` 의 인라인 `overflow` 를 그대로 쓰고, 시트는 `html`(documentElement) 의 인라인 `overflow` 를 쓴다. 각자 자기 것만 저장·복원하므로 여닫는 순서와 무관하게 "하나라도 열려 있으면 잠김"이 성립한다. **승인된 modal·modal-content 를 건드리지 않는다.**
`scrollLockNote` 도 코드가 실제로 하는 일로 고쳤다.

**재검증 (실제 dist 모듈로 8단계):**

| 단계 | 결과 |
|---|---|
| 시작 | scrollable |
| 시트 열기 | LOCKED |
| 그 위에 모달 열기 | LOCKED |
| 시트만 닫기(모달 열림) | **LOCKED** ✅ (전: 풀렸음) |
| 모달도 닫기 | **scrollable** ✅ (전: 잠긴 채 남음) |
| 모달 먼저 열기 | LOCKED |
| 그 위에 시트 열기 | LOCKED |
| 모달만 닫기(시트 열림) | **LOCKED** ✅ |
| 시트도 닫기 | **scrollable** ✅ |

**남는 한계(정직 표기):** 이 분리는 modal 계열과의 충돌만 없앤다. 앞으로 또 다른 컴포넌트가 `html` 인라인 `overflow` 를 쓰면 같은 문제가 생긴다 — 그때는 공용 잠금 장치를 따로 만들어야 한다. 코드 주석과 manifest 에 적었다.

# 13. 독립 검증 3회차 FAIL → 고친 것 (0.6.4 → **0.6.6**)

3회차 판정 **FAIL** — ❌(a) 2건 · ❓(c) 1건. 보고서 `4-verification-independent-r3.md`.
**river ②(다크 칸)는 완전히 닫혔다**고 판정됐다(라이트→다크→라이트 반복으로 "앞 테마가 남는" 함정까지 확인). river ① 의 웹 CSS 자체도 맞고 PC 과잉 삭제도 없다고 확인됐다. 문제는 **그 변경의 파급 두 곳**이었다.

## ❌(a)-1 안드로이드가 누름 표시를 통째로 잃었다 — **고침**

**⭐ 가 놓친 것이다.** Compose 생성기는 `hovered || pressed -> "hover"` 로 **누름을 hover 칸에 담고**(`kotlin-components.mjs:88-92`), 그 칸의 값을 웹 CSS 에서 읽어 온다. 그런데 포트는 `:active` 를 **원래 읽지 않았다**. 그래서 `:is(:hover, :active)` 를 쪼개는 순간 LG 3칸(`primary|lg|hover` 등)이 전부 Default 색이 됐다 — 웹에서 "누름은 전 크기 유지"라고 정한 것과 **정반대 결과**다.
`ui:build:check` 는 재생성 일치만 보므로 **틀린 값이 굳어도 초록**이었다.

**고친 방법:** `kotlin-compose.mjs` 의 button 계획에서 "hover" 칸을 만들 때 웹의 `:hover` 와 `:active` 를 **둘 다 켜서** 읽게 했다. 어느 쪽이 걸리든 그 칠을 가져온다.
- LG → `:active` 가 걸려 **누름 칠 복구** ✅
- PC 크기 → 두 규칙이 같은 토큰이라 결과 불변 ✅

**재생성 확인:** `S1ButtonSpec.kt` 의 `primary|lg|hover` 가 다시 `colorButtonBgPrimaryHover` 를 가리킨다(secondary·blue-line 도 동일).

## ❌(a)-2 모바일 안내 화면이 없어진 Hover 를 아직 보여줬다 — **고침**

`registry/components/button.json` 의 `harness.mobileColumns` 는 **2026-05-11 부터** 모바일 표에 Hover 를 두지 말라고 적어 두었는데, 가이드 JS 가 PC 와 같은 `states` 배열을 그대로 써서 무시하고 있었다(옛 부채). 이제는 배포본에서 실제로 걷어냈으므로 **화면이 사실과 다른 말을 하는 상태**가 됐다.

**고친 방법:** 모바일 표만 `hover` 를 뺀 목록으로 그린다.
**재측정:** 모바일 Button 표 칸이 `Default · Pressed · Disabled` 3개로 바뀌었다(전: Default·Hover·Pressed·Disabled). Pressed 칸은 그대로 진한 칠(`rgb(39,71,185)`)이라 눌린 모습이 남아 있다.

## ❓(c) "모바일 버튼"이 `data-size="lg"` 하나만 뜻하나 — **완성했다(질문으로 올리지 않음)**

밀도 감싸개(`data-s1-break="mobile"` + 크기 생략)로 만든 48px 버튼은 여전히 마우스오버 칠을 하고 있었다. Input 선례는 이 경우까지 막는데(`input.css:110`) Button 은 **절반만 베꼈던** 것이다.

river 지시("모바일 버튼에는 호버 없게")의 뜻은 **화면에 서는 모바일 버튼**이고, 감싸개로 만든 48px 도 그것이다 — 어느 속성으로 선언했는지는 표기 방식 차이일 뿐이라 판단해 **질문으로 올리지 않고 Input 과 같은 형태로 완성했다.**

```
:hover:not(:disabled):not([data-size="lg"]):is([data-size], :not([data-s1-break="mobile"] *))
```

자기가 크기를 직접 적었으면 그쪽이 이긴다(밀도 정책의 기존 규칙과 같다).

**재측정** (실제 dist 선택자로 `querySelectorAll` 대조):

| | 높이 | hover 걸림 |
|---|---|---|
| 감싸개만(크기 생략) | 48 | **안 걸림** ✅ |
| 감싸개 안 + `data-size="md"` 직접 | 44 | 걸림 ✅ (직접 지정이 이긴다) |
| PC 지면 `md` | 44 | 걸림 ✅ |
| PC 지면 `lg` | 48 | 안 걸림 ✅ |

**전수 재집계** — ⭐ 가 처음 적은 수치(lg 44 / md 18 / xsm 16 / xxsm 32)는 **틀렸다.** 다른 화면 상태에서 세어 버튼 수 자체가 어긋났다. 독립 검증 3·4회차가 각각 따로 잰 값이 서로 일치하며 그쪽이 맞다:

| 크기 | 버튼 수 | hover 걸림 | 누름 걸림 |
|---|---|---|---|
| **lg** | 60 | **0** | 54 |
| md | 22 | 16 | 16 |
| xsm | 6 | 6 | 6 |
| xxsm | 42 | 42 | 42 |

(빠진 수 = 비활성 버튼.) **PC 과잉 삭제 없음.**

`text-button` 은 아직 모바일에서도 hover 가 산다(검증자 곁가지 지적). river 지시는 바텀시트의 버튼과 Button 컴포넌트에 대한 것이었고, **또 다른 승인된 컴포넌트를 지시 없이 고치지 않았다.** 5-human-review 에서 묻는다.

# 15. 승인 후 반영 — Text Button 모바일 hover (0.6.7 → **0.6.10**)

river 승인과 함께 받은 지시: **"텍스트버튼도 A로 빼줘"**(2026-09-15).

## 고친 것

`text-button.css` 의 `:is(:hover, :active)` 를 Button 과 같은 방식으로 나눴다. 이 컴포넌트는 **크기 축이 없어**(`sizes: []`) LG 로 가려낼 수 없으므로 **화면 구분 선언**으로 가른다 — Input(`input.css:110`)과 같은 형태다.

```
@media (hover: hover) {
  [data-s1-component="text-button"]:not([data-break="mobile"]):is([data-break="pc"], :not([data-s1-break="mobile"] *)):hover:not(:disabled)
}
```

누름(`:active`) 밑줄은 어디서나 그대로다.

## 막혔던 것 — 이식본 CSS 해석기 — **고침**

플랫폼 이식본이 쓰는 `css-model.mjs` 가 `:not()` 안의 **자손 선택자를 지원하지 않아** 빌드가 멈췄다(`:not()/:is() 안에서는 복합 선택자 하나만 지원합니다: [data-s1-break="mobile"] *`).

Input 과 Button 이 이미 같은 형태를 쓰는데도 안 터진 이유: Button 은 `:is([data-size], …)` 의 **앞 가지가 항상 맞아**(이식본 요소는 늘 `data-size` 를 단다) `.some()` 이 짧게 끝나 뒷가지에 닿지 않았다. **우연히 피하고 있었던 것**이다. 크기 축이 없는 Text Button 은 곧바로 걸렸다.

**고친 방법:** `matchesRelative` 가 자손 결합자를 만나면 전체 선택자 대조(`matchesSelector`)로 넘긴다 — 오른쪽 끝부터 조상을 거슬러 맞추므로 브라우저와 같은 결과다. 낡은 주석("자손 결합자는 배포본에 없다")도 고쳤다.

한 번 「기본으로 주고 모바일에서 거둔다」 두 줄로 우회해 봤으나 **검사기 두 개가 막았다** — `ui:test`(밑줄 계약)와 `ui:density`(`:not([data-size])` 누락). 우회 대신 원인을 고쳤다.

## 검사기 강화 (약화 아님)

`ui:test` 의 text-button 검사가 `:is(:hover, :active)` 라는 **문자열 모양**을 보고 있어서 구조를 나누면 실패했다. 모양 대신 **뜻**을 보도록 고치되 **더 조이는 쪽으로** 바꿨다:

| 종전 | 지금 |
|---|---|
| `:is(:hover, :active)` 에 밑줄이 있나 (1개) | 누름에 밑줄 · 누름이 색을 안 바꾸나 · 마우스오버에 밑줄 · 마우스오버가 색을 안 바꾸나 · `@media (hover: hover)` 안인가 · **모바일 억제 선택자가 있나** (6개) |

**적대 테스트:** 모바일 억제 부분을 지우고 돌렸더니 `text-button hover must be suppressed on mobile …` 로 **막혔다** ✅
