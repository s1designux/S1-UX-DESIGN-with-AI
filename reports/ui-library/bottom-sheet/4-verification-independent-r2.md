## ❌(a)-1 스크롤 잠금 — **닫힘 (직접 재현)**

⭐ 의 8단계 재검증 결과는 근거로 쓰지 않았다. 1회차에 내가 재현율 100% 로 잡은 **그 순서 그대로** 다시 돌렸고, 이번엔 **실제 마우스 휠 입력**으로 잠금 여부를 판정했다.

> 방법 주의: `window.scrollTo` 는 `overflow:hidden` 이어도 먹는다(프로그램 스크롤은 막히지 않는다). 그래서 1회차식 스타일 대조에 더해 **진짜 휠 스크롤을 넣고 `scrollY` 가 움직이는지**로 판정했다. 아래 "스크롤됨"은 휠 5틱 후 `scrollY` 값이다.

| 단계 | html/body 인라인 | 휠 스크롤 결과 | 기대 | |
|---|---|---|---|---|
| 0 아무것도 안 열림 | (없음)/(없음) | **500 이동** | 풀림 | ✅ |
| 1 시트 열기 | hidden/(없음) | **0 (안 움직임)** | 잠김 | ✅ |
| 2 시트 위 모달 | hidden/hidden | 0 | 잠김 | ✅ |
| 3 **시트만 닫기(모달 열린 채)** | (없음)/hidden | **0** | 잠김 | ✅ (1회차 ❌) |
| 4 **모달 닫기(전부 닫힘)** | (없음)/(없음) | **500 이동** | 풀림 | ✅ (1회차 ❌) |

역순도 같은 방식으로 돌렸다 — 모달→시트 열기 → 모달만 닫기(시트 열린 채) = **0**, 시트 닫기 = **500 이동**. 모달만 여닫기·시트만 여닫기도 각각 정상.
**1회차의 치명적 증상(다 닫았는데 페이지가 영구 잠김)은 재현되지 않는다.**

`modal.js`·`modal-content.js` 는 **변경되지 않았다**(`git status` 에 모달 파일 0건) — 승인된 것을 건드리지 않았다는 주장도 확인했다.

**manifest 거짓 주장도 정정됐다.** `bottom-sheet.manifest.json` 의 `scrollLockNote` 는 이제 "열린 **시트** 수를 세고 **모달은 세지 않는다**, 대신 잠그는 자리를 나눈다(modal 계열=body · 시트=html)" 로 적혀 있고, 이는 코드가 실제로 하는 일과 일치한다.

**남는 한계(면죄부 아님 · manifest 가 스스로 적어 둠):** 앞으로 다른 컴포넌트가 `html` 인라인 overflow 를 쓰면 같은 충돌이 난다. 지금 고칠 것은 없다.

## 관찰 (❌ 아님 · 통과를 막지 않음)

### ① `allowed-remote-keys.json` 의 `check24` 별칭 — 판단은 **타당하다. 다만 불필요했다.**

물어본 것에 답한다.

- **권한이 넓어지지 않는다 ✅** — `check24` 의 값이 `check` 와 **완전히 같은 키**(`5ab251e0…`)다. 이 파일을 읽는 쪽(`ui-library-contract-check.js`)은 `new Set(Object.values(...))` 로 **값 집합**만 본다. 값 집합이 그대로이므로 새 외부 컴포넌트를 허용한 것이 아니다. 키 기준 판단 원칙에 어긋나지 않는다.
- **그런데 넣지 않아도 통과했다** — 검사는 `allowed.has(icon.sourceKey)` 뿐이고 그 값은 `check` 로 이미 등재돼 있었다.
- **부작용 하나** — `icon-key-consistency-check.js` 가 세는 `allowed` 개수가 26 → 27 이 되어, 통과 문구의 "허용목록 N키는 설치기 밖 사용분"이 1 만큼 부풀었다. 어떤 검사도 이 수를 단언하지 않아 깨지는 것은 없다.
- **이미 제자리가 있다** — 이 파일에는 이름이 다를 때 쓰라고 만든 `nameAliases` 블록이 있고, 주석이 "별칭은 값이 같을 때만 인정한다"고 적어 두었다.

권고: 되돌리거나 `nameAliases` 쪽으로 옮기는 편이 파일의 뜻에 맞다. **지금 상태로도 안전하므로 PASS 를 막지 않는다.**

### ② 검수 화면(`ui-review.html`)의 시트 패널은 아직 360 이 아니다

안내 화면은 이번에 360 으로 고정됐지만, **river 가 승인 판단을 하는 검수 화면은 안 됐다.** 실측: 창 1024 에서 패널 **202px**, 창 1600 에서 **306px**(제목↔닫기 간격은 각각 64·168 이라 1회차처럼 맞붙지는 않는다).

배포본 규칙(`max-width:360px; width:100%`) 자체는 정상 동작이고 실기기에서는 화면 폭이 곧 시트 폭이라 틀린 표시는 아니다. 다만 **river 는 정본 폭 360 의 모양을 보고 승인하게 되므로** 안내 화면과 같은 처리를 권한다. ❌ 로 세지 않는다(검수 하네스 쪽 표시 문제).

### ③ 초점 덫 재귀 — 한 번 관측, **5회 시도 재현 실패**. NOT_VERIFIED 로 남긴다.

검증 도중 한 탭의 콘솔에 `Maximum call stack size exceeded`(`bottom-sheet.js:103` · `modal.js:88` — 둘 다 `handleFocusIn` 의 `focusFirst()` 줄)가 대량으로 쌓인 것을 관측했다.

그 뒤 **깨끗한 새 탭에서 5가지 조합을 의도적으로 돌렸으나 한 번도 재현되지 않았다** — 시트 단독 / 시트+모달 / 모달→시트 역순 / 겹친 상태에서 한쪽만 닫기 / **시트 2개 동시 열고 초점을 바깥으로 밀기**. 전부 오류 0건이고, 갓 연 `components.html`·`ui-review.html` 도 콘솔 오류 **0건**이다.

구조상 근거만 적어 둔다: `handleFocusIn`·`handleFocusOut` 어디에도 재귀 깊이 가드가 없어, 초점을 서로 당기는 상황이 만들어지면 원리상 멈출 장치가 없다. **이번 작업이 넣은 코드가 아니라 modal 과 공유하는 기존 구조다.** 재현 경로를 못 찾았으므로 ❌ 로 세지 않고, "확인 못 함"으로 남긴다.

### ④ 좁은 화면에서 안내 화면 상태 매트릭스가 가로로 스크롤된다

창 375 에서 칸 3개(각 408)가 한 줄에 서서 1358px 이 된다. 다만 상위 컨테이너가 `overflow-x:auto` 라 **페이지 전체가 가로로 새지는 않고**(문서 scrollWidth 375) 그 칸만 옆으로 밀린다. 칸 최소 폭을 300 으로 두었던 때도 900px 이라 같은 상황이었다 — **이번 변경이 만든 것이 아니다.** `408` 은 Bottom Sheet 상태 매트릭스 한 곳에만 인라인으로 적용돼 다른 컴포넌트에 영향이 없다(확인함).

## §5 상태 플래그를 되돌리지 않은 판단 — **정당하다**

판정 근거는 하나다. **그 선택이 검사를 느슨하게 만들었나, 엄격하게 만들었나.**

`status` 를 `draft` 로 되돌렸다면 `ui:guide:render` 는 두 컴포넌트를 **건너뛰고** 초록을 냈을 것이다. 유지했기 때문에 이번 초록은 두 컴포넌트를 **실제로 그려서** 낸 것이다. 즉 되돌리지 않은 선택은 검사 범위를 **넓혔다**. 자기승인으로 초록을 세탁한 것이 아니다.

여기에 ①⭐ 가 §5 에 사실과 이유를 먼저 적었고 ②1회차 초록을 2회차 근거로 재사용하지 않았고 ③판정을 검증자에게 넘겼다. 숨긴 것이 없다.

그리고 지금 이 검증이 PASS 이므로 `verified` 라는 라벨은 **사후적으로도 사실이 됐다.**
