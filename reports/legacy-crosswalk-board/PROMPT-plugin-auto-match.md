## 프롬프트

별도 폴더에서 해줘 — **레거시 이름 결정표를 Figma 설치/검수기 플러그인의 검수 기능에 넣고, 그 자리 UI를 조정하는 작업**이야.

### 배경 (읽고 시작해)

레거시 가이드 두 벌(A = SW UX GUIDE V2.4 · B = S-1 Component Set)의 부품 이름을 지금 정본 이름에 맞추는 일은 **저장소 쪽에서는 끝났다.**

- river 결정 23건은 `reports/legacy-crosswalk-board/crosswalk.json` 의 `items[].machine` 에 기계가 읽는 형태로 들어 있다.
- 조회기 `npm run legacy:resolve -- "<A|B>:<레거시 이름>" [--state x] [--size y] [--variant z] [--id 540:3690]` 가 이것을 읽어 답한다. 전체 훑기 `-- --all --json`.
- 공통 판독부 `scripts/lib/legacy-name-map.js` (`resolve()` · `loadFacts()` · `loadIdToSets()` · `canonAxisValue()`).
- 정본 이름의 **유일한 사전**은 `registry/components/component-facts.json` 의 `variantAxes` 다. 여기 없는 세트·축·값은 **답으로 내보내지 않는다**(하드룰 H6②).
- **Gate 52** 가 결정↔표 일치와 「정본에 없는 이름」을 막는다. 적대 시험 5종 + 조회기 회귀 시험 6종: `npm run legacy:selftest`.
- 현재 훑기 결과: 레거시 126세트 = 붙음 88 · 결정 전 34 · 배치 규칙 2 · 레거시에만 2 · 모름 0.

**그런데 플러그인은 이 표를 전혀 보지 않는다.** `plugins/figma-vars-installer/src/audit-engine.ts` 의 GUI 검수는 레거시 인스턴스 이름과 정본 이름의 **글자 유사도 점수**(`scoreNameSimilarity` → `rankSuggestions`)로 후보를 늘어놓고, 사람이 드롭다운에서 고른다. river 가 "사람이 직접 컴포넌트 이름을 매칭해줘야 한다"고 한 자리가 여기다.

### 이번에 할 일

**① 결정표를 플러그인 안에 심는다(생성물).**
플러그인은 Figma 안에서 돌아 저장소 파일을 읽지 못한다. `vars-data.ts` 와 같은 방식으로 **생성된 데이터 파일**을 만든다.

- 새 파일 예: `plugins/figma-vars-installer/src/legacy-map-data.ts` — **손편집 금지·생성물**임을 머리말에 명시.
- 생성기 예: `scripts/build-legacy-map-data.js` — `scripts/lib/legacy-name-map.js` 를 그대로 재사용해 126세트 전수 결과를 굽는다(레거시 세트 이름·노드 id·출처 → 정본 세트 이름 · 축 값 대응 · 판정 종류 · 근거 결정 번호).
- **정본은 여전히 `crosswalk.json` 이다.** 생성물이 밀리면 막도록 **Gate 52 에 "구운 데이터가 최신인가" 판정을 추가**한다(기존 `--check` 와 같은 자리, 래칫 아님 — 재생성하면 끝나므로 그냥 실패시킨다).

**② 검수 기능이 그 표를 먼저 본다.**
`audit-engine.ts` 의 매칭 경로(`rankSuggestions` · `ManualMapCandidate` 를 만드는 `1220~1480` 근처 · 변형 고르기 `pickVariantTarget`)에서:

- 결정이 있는 레거시 세트 → **후보를 늘어놓지 않고 그것으로 정한다.** 화면에는 「결정으로 정해짐 · 근거 D-xx」를 보여준다.
- 결정의 축 값 대응이 있으면 **variant 도 그 값으로** 고른다(예: 레거시 `selected` → 정본 `State=Focus`).
- 결정이 없거나 `결정 전`·`모름` → **지금처럼 후보 목록**을 보여주되 「아직 안 정함 — 고르면 river 결정이 아니라 이번 한 번의 선택」이라고 분명히 표시한다.
- `레거시에만 있음`·`배치 규칙(부품 아님)` → **교체 대상이 아니라고 답하고 후보를 권하지 않는다**(잘못된 교체 유도 방지).
- 이름이 겹쳐 붙는 곳이 갈리면(`ambiguous`) 노드 id 로 구분해 되묻는다.

**③ UI 조정.** `plugins/figma-vars-installer/src/ui.html` 의 수동 매핑 카드(1479행 근처 `manualMap`)와 모듈 부품 행(1667행 근처)이 같은 배선을 쓴다. 지금은 전부 "가장 비슷한 정본을 맨 위에 제안했습니다"라는 한 가지 말투다. 이것을 **판정 종류별로 다르게** 보이게 한다.

- 정해진 것 / 아직 안 정한 것 / 교체 대상 아님 이 **한눈에 구분**돼야 한다(river 는 비개발자 UX 디자이너다 — 색·배지·문구로 구분, 영어 상태 이름 노출 금지).
- 결정으로 정해진 것은 드롭다운을 **기본으로 접어 두고**, 바꾸고 싶을 때만 펼치게 한다.
- 근거(D-xx)는 **무슨 결정인지 한 줄 사람 말**로 보여준다(번호만 던지지 않는다 — `crosswalk.json` 의 `무엇`·`quote2` 를 쓴다).
- 개수 요약(1472행 `수동매핑 N`)도 새 구분에 맞춰 고친다.

### 꼭 지킬 것

1. **정본에 없는 이름을 만들지 마라.** 정본 이름 사전은 `component-facts.json` 의 `variantAxes` 하나뿐이다. 근거가 없으면 `needs-decision` 으로 올린다(하드룰 H6②·Gate 34).
2. **결정표를 손으로 고치지 마라.** 고칠 일이 생기면 `crosswalk.json` 쪽을 고치고 `npm run legacy:apply` 로 내린다. Gate 52 가 대조한다.
3. **자동 교체를 넓히지 마라.** 결정이 있는 것만 자동으로 정해지고, 나머지는 사람이 고른다. "비슷하니 자동으로 바꿔주기"는 금지다.
4. **UI 를 건드렸으면 렌더 1회 확인 의무**(`npm run shot -- ... out.png` → 스크린샷 육안 대조). 플러그인 UI 는 Figma 안에서 도는 화면이라, 가능하면 실제 플러그인으로도 한 번 띄워 보고 안 되면 「미확인」으로 명시해라.
5. **검증은 분리한다** — 만든 자 ≠ 검증하는 자. 🤖 `component-verifier` 를 실제 spawn 해서 대조시킨다. 이 작업은 검수 판정 자체를 바꾸는 일이라 self-certify 하지 마라.
6. **다시 심어야 산출물이 보인다** — 설치기는 이미 있는 것을 건너뛴다. 플러그인을 Figma 에서 **다시 등록/재실행**해야 바뀐 화면이 보인다.

### 기계검사 (끝내기 전 전부 초록이어야 함)

| 명령 | 무엇 |
|---|---|
| `npm run installer:check` | 플러그인 타입 검사 |
| `npm run installer:build` | 플러그인 번들·zip |
| `npm run legacy:check` | Gate 52 본체(결정↔표) |
| `npm run legacy:selftest` | 적대 5종 + 회귀 6종 |
| `npm run gate:check` | 전체 검문소 |

### river 가 준 작업 방식

- **신규를 만들 때는 끝까지 혼자 가지 말고 중간에 보여주고 확인받는다.** 화면이 바뀌는 일이니 UI 안을 먼저 보여 줘라.
- 보고는 결과 중심으로 짧게 — 결론 한 줄 굵게 · 쉬운 말 · 10줄 안팎 · 과정 서술과 파일 이름·명령어는 빼고. **작업 중 중간 보고 0회.**
- 개수는 문서에서 베끼지 말고 기계로 다시 뽑아라.

### 첫 질문 (착수 전에 river 에게)
