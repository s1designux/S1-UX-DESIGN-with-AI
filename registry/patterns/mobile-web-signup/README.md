# Mobile Web Signup

모바일 웹에서 약관 동의와 외부 본인인증을 거쳐 통합계정 정보를 만들고, 가입 완료 뒤 앱 설치를 안내하는 회원가입 패턴이다.

## 현재 상태

| 항목 | 값 |
|---|---|
| 패턴 ID | `mobile-web-signup` |
| 상태 | promoted |
| 플랫폼 | Mobile Web |
| 현재 화면 상태 | 11개 |
| Figma Section | `1744:1782` |
| 기준 서비스 | MoDU App |

## 언제 사용하는가

- 모바일 웹에서 통합계정 회원가입을 제공할 때
- 약관 동의 뒤 외부 본인인증을 연결할 때
- 기존 서비스 아이디가 있으면 재사용과 새 아이디 생성을 함께 제공할 때
- 웹 가입 완료 후 앱 설치를 안내할 때

## 이 패턴이 해결하는 것

- 우리 서비스가 통제하지 않는 본인인증 화면을 임의로 재현하지 않는다.
- 기존 계정이 있는 사용자에게 중복 가입 대신 아이디 재사용 선택을 제공한다.
- 아이디·비밀번호·이메일 입력과 키보드 상태를 같은 Web 정본 셸로 유지한다.
- 약관·비밀번호 조건·도메인 선택 같은 보조 상태를 기본 화면과 일관된 배경 위에 제공한다.

## 반드시 유지할 규칙

1. 모든 우리 화면은 `Mobile Header / Platform=Web` 정본을 사용하고 브라우저 주소창을 포함한다.
2. 약관 동의 다음 단계는 외부 본인인증이며, 외부 화면은 우리 컴포넌트로 재현하지 않는다.
3. 인증 뒤 신규 계정과 기존 아이디 보유 흐름을 구분한다. 기존 아이디가 있어도 새 아이디를 선택할 수 있어야 한다.
4. 비밀번호는 8~15자의 확정 문구와 별도 조건 안내를 사용한다.
5. 이메일 도움말로 비밀번호 찾기 내용을 표시하지 않는다.
6. 오버레이 화면의 배경은 대응하는 기본 화면과 완전히 같아야 한다.
7. 웹 완료 화면은 앱 설치 안내이며, 앱 경로의 완료 화면과 혼동하지 않는다.
8. 360×780 화면 루트 배경은 `color/bg/level-0`을 사용한다.
9. 패턴 Section 자체는 fill 없이 투명하게 유지한다.
10. 기존 아이디·비밀번호 조건·이메일 도메인 오버레이에서는 NavBar가 Dim보다 앞, Bottom Sheet·Modal보다 뒤에 있어야 한다.
11. `NavBar / Web + Keyboard`는 앱과 동일하게 키보드와 하단 내비만 사용하며, 그 사이에 브라우저 도구 모음을 넣지 않는다.

## 서비스별 변경 가능 범위

- 서비스명과 앱 아이콘
- 외부 본인인증 사업자와 실제 연결 방식
- 기존 아이디 목록과 마스킹 정책
- 가입 완료 뒤 앱 설치 링크와 보조 행동

변경하더라도 외부 인증 경계, 기존 아이디 선택권, 입력 조건, Web 셸 규칙은 유지한다.
