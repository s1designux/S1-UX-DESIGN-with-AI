# Mobile Web Signup 흐름과 이유

## 기본 흐름

| 코드 | 단계 | 사용자·시스템 상태 | 다음 조건 |
|---|---|---|---|
| `1` | 약관 동의 | 필수 약관과 만 14세 이상 여부 확인 | 본인인증 실행 |
| `2` | 외부 본인인증 | 외부 사업자가 인증을 처리 | 취소 시 `1`, 성공 시 계정 확인 |
| `3` | 아이디 입력 | 신규 아이디 입력 또는 기존 아이디 분기 복귀 | 아이디 확정 |
| `4` | 비밀번호 입력 | 비밀번호와 확인값 입력 | 조건 충족 후 다음 |
| `5` | 이메일 입력 | 이메일 주소와 도메인 입력 | 이메일 확정 |
| `6` | 앱 설치 안내 | 웹 회원가입 완료 | 앱 설치 또는 다음에 설치 |

## 분기

### `1a` — 약관 상세

사용자가 동의 전에 약관 내용을 확인한다. 현재 확인된 제1조·제2조까지만 제공하며 확인되지 않은 조항을 생성하지 않는다.

### `2a` — 이미 가입된 회원

본인인증 결과 이미 회원이면 안내 모달을 제공한다. 계정 존재를 숨기는 로그인 오류와 달리, 본인인증이 끝난 회원가입 흐름에서는 기존 아이디를 안내할 수 있다.

### `2b` — 기존 아이디 선택

홈페이지·웹뷰어에서 사용하던 아이디가 있으면 재사용할 수 있다. 사용 중인 아이디는 비활성으로 구분하고, 사용자가 원하면 새 아이디 입력으로 돌아갈 수 있다.

### `4a` — 비밀번호 조건

입력 화면을 떠나지 않고 조합 규칙을 확인한다. 조건 안내는 입력값의 성공·실패 판정이 아니라 정책 설명이다.

### `5a` — 이메일 도메인 선택

자주 쓰는 도메인을 선택하거나 직접 입력으로 전환한다. 선택 결과는 이메일 입력 화면에 반영한다.

## 사용하지 않는 흐름

- 외부 본인인증 사이트를 우리 디자인 시스템으로 복제하는 흐름
- 이메일 입력 화면에 비밀번호 찾기 도움말을 표시하는 흐름
- 기존 아이디가 있다는 이유로 새 아이디 선택을 막는 흐름
- 모바일 웹에서 앱 전용 상태바나 앱 완료 화면을 사용하는 흐름
