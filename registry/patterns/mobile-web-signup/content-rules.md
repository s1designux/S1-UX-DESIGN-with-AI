# Mobile Web Signup 콘텐츠·접근성·컴포넌트 규칙

## 외부 본인인증

- 인증 사업자의 화면을 우리 컴포넌트로 재현하지 않는다.
- 우리 화면에서는 외부 단계로 이동한다는 사실, 취소와 다음 진행만 설명한다.
- 취소하면 약관 화면으로 돌아간다. 외부 사업자가 처리하는 실패 화면을 별도 생성하지 않는다.

## 입력과 키보드

- 아이디는 영어 소문자와 숫자 4~12자 기준을 안내한다.
- 비밀번호는 영문·숫자·특수문자 조합 8~15자 기준을 안내하고 마스킹·보기 기능을 제공한다.
- 비밀번호 확인란이 CTA와 키보드에 일부 가려지는 상태는 현재 원본의 의도된 표현이다. 라벨과 다음 행동은 식별 가능해야 한다.
- 이메일 도메인은 선택과 직접 입력을 모두 제공한다.
- 키보드 화면은 별도 그림이 아니라 `NavBar / Platform=Web + Keyboard` 정본을 사용한다.
- `Web + Keyboard`는 앱과 같은 `키보드 + 하단 내비` 구조이며, 키보드와 하단 내비 사이에 브라우저 도구 모음을 넣지 않는다. 브라우저 도구 모음은 키보드가 없는 기본 Web형에만 유지한다.

## 기존 계정

- 본인인증 뒤 기존 계정이 확인된 경우에만 기존 아이디를 안내한다.
- 선택 가능한 아이디, 기본 아이디, 이미 사용 중인 비활성 아이디를 명확히 구분한다.
- 기존 아이디를 강제하지 않고 `새 아이디 사용`을 제공한다.

## 오버레이

- 약관↔기존 회원 모달, 아이디↔기존 아이디 시트, 비밀번호↔조건 모달, 이메일↔도메인 시트의 배경은 각각 완전히 같아야 한다.
- Modal과 Bottom Sheet 정본을 유지하고, 정본에 없는 설명·추가 옵션만 승인된 sibling 조합으로 확장한다.
- 닫기 버튼은 24×24의 충분한 터치 영역과 접근 가능한 이름을 제공한다.
- 기존 아이디·비밀번호 조건·이메일 도메인 오버레이에서는 NavBar가 Dim보다 앞에 보여야 한다. Bottom Sheet·Modal은 NavBar보다 앞에 둔다.

## 정본 컴포넌트

- Mobile Header (`Platform=Web`)
- StatusBar / NavBar
- Checkbox
- Input / Select Box
- Button
- Mobile Modal
- Bottom Sheet / Bottom Sheet Option

컴포넌트 시각과 크기는 현재 로컬 Core 정본을 우선하며 nested 인스턴스를 직접 늘리거나 분리하지 않는다.

## 화면 배경

- 360×780 화면 루트 배경은 `color/bg/level-0`을 사용한다.
- `color/bg/level-1`을 화면 루트에 사용하지 않는다.
- NavBar 정본 내부의 키보드 깊이 표현처럼 컴포넌트가 소유한 배경 토큰은 화면에서 직접 바꾸지 않는다.
- 패턴 Section 자체에는 fill을 두지 않는다. 화면 사이 여백은 투명하고, 각 화면 루트가 자신의 배경을 소유한다.
