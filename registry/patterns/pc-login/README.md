# PC Login

PC 웹 서비스에서 사용자가 아이디·비밀번호를 입력하고 서버 판정을 거쳐 서비스에 들어가게 하는 로그인 패턴이다. 화면 가운데의 로그인 묶음(CI · 입력칸 2개 · 로그인 버튼 · 보조 링크)은 패턴 전용 부품 `PC Login Box` 하나로 만들고, 보조 링크 자리는 서비스마다 바꿔 끼우는 슬롯(`Links`)이다.

## 언제 사용하는가

- PC 웹 서비스에 아이디와 비밀번호로 로그인할 때
- 브라우저 창 안에서 서비스 첫 화면이 로그인인 경우(맨 위 줄 + 가운데 로그인 묶음 + 맨 아래 띠)
- 서버가 계정 불일치·잠금·사용 중지를 판정하는 로그인 흐름일 때

## 이 패턴이 해결하는 것

- 입력이 끝나기 전 잘못된 제출을 막는다(버튼 비활성).
- 로그인 실패 시 어느 값이 틀렸는지, 계정이 있는지를 드러내지 않는다.
- 여러 번 실패한 경우와 막힌 계정을 같은 자리·같은 방식으로 안내해 사용자가 헤매지 않게 한다.
- 서비스마다 다른 보조 링크(회원가입·찾기 등)를 묶음 부품을 고치지 않고 바꿔 끼울 수 있게 한다.

## 반드시 유지할 규칙

1. 아이디 또는 비밀번호가 비어 있으면 로그인 버튼은 비활성이다.
2. 클라이언트에서 아이디·비밀번호 형식을 판정하지 않는다.
3. 로그인 실패는 서버 응답 후 하나의 통합 오류로 표현한다 — 두 입력칸을 함께 오류로 표시하고, 문구는 비밀번호 칸 아래에 한 번만 둔다.
4. 실패 안내를 로그인 묶음 위의 별도 빨간 상자로 따로 띄우지 않는다.
5. 비밀번호는 마스킹하며 비밀번호 칸에는 보기 아이콘(Input `Password Icon`)을 켠다.
6. 로그인 묶음은 `PC Login Box` 인스턴스로 쓴다. 칸 사이 간격(CI→칸 34 · 칸 사이 10 · 칸→버튼 32 · 버튼→링크 16)과 폭 300 은 부품이 갖고 있으므로 화면에서 다시 맞추지 않는다.
7. 화면마다 다른 것은 묶음 안 입력칸·버튼의 상태와 문구뿐이다.

## 서비스별 변경 가능 범위

- 맨 위 줄·창틀의 `[서비스명]`
- 보조 링크 슬롯 `Links` 의 내용(링크 제공 여부·종류). 링크를 빼면 짝이 되는 구분선도 함께 뺀다
- 재시도 제한 횟수와 잠금 시간 문구의 숫자
- 로그인 성공 후 이동 목적지

변경하더라도 위의 필수 규칙과 `flow.md` 의 보안 원칙은 유지한다.

## 넣지 않는 것

아이디 저장 · 언어 목록 펼친 화면 · 약관 팝업 · 비밀번호 보기/숨기기 화면 · 회원가입·아이디/비밀번호 찾기 흐름 — 이유는 `states.md` 「패턴 범위 밖」.
