# PC Login 콘텐츠·보안·부품 규칙

## 입력

- 아이디·비밀번호 형식은 입력 중에 판정하지 않는다.
- 두 값 중 하나라도 비어 있으면 로그인 버튼을 비활성(Button State=Disabled)으로 둔다.
- 비밀번호는 마스킹하고, 비밀번호 칸은 Input `Password Icon` 을 켠다. 아이디 칸은 끈다.
- 입력칸·버튼 크기는 PC 정본 MD(높이 44) 그대로 쓴다. 레거시의 50 으로 늘리지 않는다.

## 로그인 실패

- 서버가 돌려준 실패는 아이디·비밀번호를 묶은 하나의 오류로 표현한다. 어느 값이 틀렸는지 특정하지 않는다.
- 두 입력칸 모두 Input State=Error 로 둔다. 안내 문구는 비밀번호 칸의 Message=On 자리에 **한 번만** 둔다(아이디 칸은 Message=Off).
- 안내 문구 자리는 가로 FILL · 세로 HUG — 두 줄 문구가 접히거나 잘리지 않게 한다.
- 로그인 묶음 위에 별도 빨간 상자로 오류를 띄우지 않는다(포털 화면의 방식은 패턴에서 쓰지 않음).
- 잠금(5회)·사용 중지 계정도 같은 자리·같은 표현을 쓰고, 문구만 다르다.
- 같은 종류 패턴 규칙: `registry/patterns/mobile-login/content-rules.md` 「로그인 실패」.

## 보조 링크 (슬롯 `Links`)

- 로그인 버튼 아래 16 에 가로 한 줄, 가운데 정렬, 항목 사이 간격 12.
- 링크는 정본 Text Button(Variant=Secondary · State=Default)을 쓴다.
- 링크 사이 구분선은 1×12, 색 `color/line/default` (기준 자료 #d9d9d9 는 레거시 값 — 정본 선 토큰으로 둔다, 두 갈래 (b)). 이 선택은 확정이다(intent.md 변경 3 · 부품 검증 4-verification 🟡(b)).
- 구분선 길이 통일 규칙은 패턴이 직접 그린 구분선끼리에만 적용한다. Footer 안 구분선(1×8)은 정본 Footer 소속이라 맞추지 않는다.
- 서비스가 링크 일부를 빼면 짝이 되는 구분선도 함께 뺀다. 구분선이 줄 끝에 남지 않아야 한다.
- 서비스별 링크 교체는 슬롯에서 한다 — 부품을 떼어 내거나(detach) 묶음 부품을 고치지 않는다.

## 화면 뼈대

- 1920×1080, 세로 쌓기: WebTabBar(101) → LoginGNB(56) → 본문(남는 높이 전부) → Footer PC(116).
- 본문은 위 여백 123, 가로 가운데. 그 안에 `PC Login Box` 인스턴스 하나뿐이다.
- 화면 바탕 `color/bg/level-0`. 색은 모두 Semantic 토큰으로 연결하고 직접 칠하지 않는다.

## 정본 컴포넌트

- WebTabBar · LoginGNB · Footer(PC) · CI(에스원/Blue) · Input · Button · Text Button
- 패턴 전용 부품: `PC Login Box` (슬롯 `Links`)

컴포넌트 시각과 크기는 현재 로컬 Core 정본을 우선한다. 알려진 정본 쪽 특성: 아이디 칸(Password Icon=false)에서 Input 의 `trail` 이 100×100 으로 남아 글자 칸 폭을 줄인다(needs-core-update, 기존 항목 — 현재 문구는 모두 들어감).

## 서비스별 문구 변경 시

- 서비스명·잠금 시간·재시도 횟수는 서비스에 맞게 바꿀 수 있다.
- 계정 존재 여부를 드러내거나 어느 값이 틀렸는지 단정하는 문구로 바꾸지 않는다.
