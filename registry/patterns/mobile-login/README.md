# Mobile Login

모바일 서비스에서 사용자가 계정 정보를 입력하고, 서버 판정과 필요한 추가 보안 확인을 거쳐 안전하게 서비스에 진입하도록 하는 로그인 패턴이다.

## 현재 상태

| 항목 | 값 |
|---|---|
| 패턴 ID | `mobile-login` |
| 상태 | promoted |
| 플랫폼 | Mobile App |
| 현재 화면 상태 | 10개 |
| Figma Section | `1562:2` |
| 기준 서비스 | MoDU App |

## 언제 사용하는가

- 아이디와 비밀번호를 이용해 모바일 앱에 로그인할 때
- 로그인 성공 후 자동 로그인 동의를 받을 수 있을 때
- 새로운 기기에서 추가 인증이나 기기 등록이 필요할 때
- 서버가 계정 정보 불일치를 판정하는 로그인 흐름일 때

## 이 패턴이 해결하는 것

- 입력 완료 전 잘못된 제출을 막는다.
- 로그인 실패 시 계정 존재 여부나 잘못된 항목을 노출하지 않는다.
- 자동 로그인처럼 보안에 영향을 주는 선택을 명시적으로 확인한다.
- 새로운 기기의 추가 인증과 기기 등록 필요성을 사용자가 이해하게 한다.
- 키보드가 열린 입력 상태도 같은 로그인 흐름 안에서 일관되게 표현한다.

## 반드시 유지할 규칙

1. 아이디 또는 비밀번호가 비어 있으면 로그인 버튼은 비활성이다.
2. 클라이언트에서 아이디·비밀번호 형식의 옳고 그름을 판정하지 않는다.
3. 계정 불일치는 서버 응답 후 하나의 통합 오류로 표현한다.
4. 어느 값이 틀렸는지 특정하지 않고 아이디와 비밀번호 입력창을 함께 오류로 표시한다.
5. 비밀번호는 마스킹하며 보기·숨기기 기능을 제공한다.
6. 자동 로그인은 사용자의 명시적인 선택을 거친다.
7. 새로운 기기는 서비스 정책에 맞는 추가 인증 또는 등록 안내를 거친다.

## 서비스별 변경 가능 범위

- 브랜드 로고와 서비스명
- 회원가입·아이디 찾기·비밀번호 찾기 링크의 제공 여부
- 추가 인증 수단의 명칭
- 보안 정책에 따른 새로운 기기 안내 문구
- 로그인 성공 후 이동 목적지

변경하더라도 위의 필수 규칙과 `flow.md`의 보안 원칙은 유지한다.
