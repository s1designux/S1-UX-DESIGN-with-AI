# Mobile Login 콘텐츠·보안·접근성 규칙

## 입력

- 아이디와 비밀번호의 형식이 맞는지는 입력 중에 판정하지 않는다.
- 두 값 중 하나라도 비어 있으면 로그인 버튼을 비활성화한다.
- 비밀번호는 기본적으로 마스킹한다.
- 보기·숨기기 제어에는 시각 아이콘뿐 아니라 접근 가능한 이름을 제공한다.
- 키보드가 열려도 로그인 버튼과 보조 링크가 가려지거나 겹치지 않아야 한다.

## 로그인 실패

- 서버가 반환한 불일치는 아이디와 비밀번호를 묶은 하나의 오류로 표현한다.
- 어느 값이 틀렸는지 특정하지 않는다.
- 두 입력창에 동일한 오류 상태를 적용한다.
- 오류 문구는 비밀번호 입력창 아래에 한 번만 제공해 중복 읽기를 피한다.
- 재시도 제한이 있는 서비스는 현재 횟수와 최대 횟수를 함께 안내할 수 있다.
- 기존 입력값을 지울지는 서비스 보안 정책에 따르되, 사용자가 무엇을 수정해야 하는지 알 수 있어야 한다.

## 자동 로그인

- 자동 로그인은 사전 선택 상태로 조용히 적용하지 않는다.
- 사용자가 취소와 확인을 구분할 수 있는 명시적인 선택을 제공한다.
- 설정 완료 안내가 필요한 경우 결과를 짧게 확인시킨다.
- 공용 기기나 기기 분실 시의 위험을 서비스 정책에 맞춰 보완 안내할 수 있다.

## 새로운 기기

- 왜 추가 인증이 필요한지 정보 보호 관점에서 설명한다.
- 새 기기 등록으로 기존 인증 기기가 해제되는 경우 확인 전에 알린다.
- 인증 완료와 로그인 완료를 같은 의미로 쓰지 않는다.
- 사용자가 해야 할 다음 행동이 본인 인증인지, 재로그인인지, 기기 등록 동의인지 명확히 구분한다.

## 모달

- 모바일 Modal 정본을 사용한다.
- 360px 화면에서 모달 폭은 300px이며 딤 영역 좌우 여백은 30px이다.
- 본문은 내용에 따라 높이가 늘어나야 하며 고정 최소 높이로 빈 공간을 만들지 않는다.
- 버튼 수는 결정의 성격에 맞춘다. 단순 알림은 Single, 취소와 확인이 필요한 결정은 Dual을 사용한다.
- 긴 문구가 잘리거나 버튼과 겹치면 안 된다.

## 정본 컴포넌트

- StatusBar
- NavBar
- CI
- Footer
- Button
- Input
- Modal

키보드 입력 상태는 별도 그림이나 빈 프레임이 아니라 `NavBar / Platform=App + Keyboard`를 사용한다. 컴포넌트 시각과 크기는 현재 로컬 Core 정본을 우선한다.

## 서비스별 문구 변경 시

- 브랜드명과 인증 수단 이름은 서비스에 맞게 바꿀 수 있다.
- 의미와 보안 수준은 유지한다.
- 계정 존재 여부를 드러내거나 어느 자격 증명이 틀렸는지 단정하는 문구로 바꾸지 않는다.
- 버튼 문구는 사용자가 다음 결과를 예측할 수 있는 동사를 사용한다.
