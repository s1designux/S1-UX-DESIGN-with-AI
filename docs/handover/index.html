S-1 디자인 시스템 운영 안내서

이 프로젝트는 S-1의 색·글자·간격(토큰)과 버튼·입력창 같은 부품(컴포넌트)을 한곳에서 관리하고, 그걸 Figma·가이드 사이트·개발자용 코드로 자동으로 내보내는 작업장입니다.

코드를 직접 만질 일은 없습니다. 운영은 Claude에게 말로 요청하는 방식입니다. 이 문서는 "무엇을 고치고 싶을 때 뭐라고 말하면 되고, 그러면 뒤에서 무엇이 바뀌는지"를 알려드립니다.

원본은 세 개뿐값은 원본 세 곳에만 적혀 있고, 나머지는 전부 거기서 자동으로 만들어집니다.
결과물은 손대지 않기사이트나 문서가 틀렸으면 그걸 고치는 게 아니라 원본을 고치고 다시 만듭니다.
새로 만들 땐 승인값을 바꾸는 건 계획 OK 한 번이면 됩니다. 새 색·새 부품을 추가할 때는 승인 문장이 따로 필요합니다.

프로젝트 규칙과 기록에 나오는 "river"는 이전 담당자입니다. 이제 여러분이 그 자리입니다.

처음 컴퓨터 세팅

새 컴퓨터에서 시작하기

한 번만 하면 됩니다. Claude에게 "이 프로젝트 처음 세팅 도와줘"라고 하면서 아래 순서를 같이 진행하세요.

  1. Claude 데스크톱 앱, Figma 데스크톱 앱, Node.js를 설치합니다. (지금 PC는 Node 20을 씁니다)
  2. GitHub의 s1designux/S1-UX-DESIGN-with-AI 저장소를 내려받습니다. 계정 권한이 필요합니다.
  3. Claude에게 "필요한 거 설치해줘"라고 하면 설치하면서 커밋 검문소도 자동으로 깔립니다.
  4. Claude에게 "Figma 열쇠 넣을 파일 만들어줘"라고 하면 빈칸 두 개를 묻습니다. Figma 파일 주소의 키, 그리고 개인 열쇠입니다. 개인 열쇠는 Figma 설정 → Personal access tokens에서 읽기 권한으로 만듭니다. 이 파일은 GitHub에 올라가지 않습니다.
  5. Figma 데스크톱에서 플러그인 → 개발 → 매니페스트로 가져오기 → plugins/figma-vars-installer/dist/manifest.json 을 등록합니다. 플러그인 폴더가 여러 개이니 이 경로를 정확히 고르세요.
  6. Claude에게 "Figma 연결 도와줘", "GitHub 로그인 도와줘"라고 해서 두 연결을 마칩니다. GitHub 로그인이 있어야 저장소에 올리고 공개 가이드 상태도 확인할 수 있습니다.
미리 알아둘 것 · 지금 Claude가 짧고 쉬운 말로 보고하고, 작업 중엔 조용히 있다가 끝에 한 번만 보고하는 방식은 이전 담당자 컴퓨터의 개인 설정입니다. 같은 방식을 원하면 그 설정 내용을 받아 "전역 규칙으로 등록해줘"라고 하세요. 이 설정이 없으면 보고가 길고 기술적인 말로 나옵니다.

수정 요청하기

이렇게 말하면, 이렇게 돌아갑니다

파란 말풍선이 여러분이 할 말입니다. 번호 중 파랗게 칠한 단계만 여러분 차례이고, 나머지는 Claude가 합니다.

토큰 값 하나 바꾸기

가장 흔한 일. 색·간격 값만 바꿀 때
이렇게 말하세요
color/bg/level-1 라이트 값을 gray/50 으로 바꿔줘

토큰 이름을 몰라도 됩니다. "1단계 배경색을 한 단계 진하게 해줘"처럼 말하면 Claude가 이름을 찾아 확인합니다. 이름 목록은 가이드 사이트 Semantic 페이지에 있습니다.

  1. 그 토큰이 어디어디에 쓰이는지 먼저 찾아 보여 줍니다.
  2. 계획을 한 번 보여 주면 확인하고 OK 합니다. 여러분
  3. 토큰 값 원본 한 줄만 고칩니다. 다크 값은 말하지 않았으면 그대로 둡니다.
  4. "한 번에 다시 만들기"로 사이트·문서·설치기를 전부 새로 씁니다.
  5. 웹 UI 키트는 값이 바뀌면 일부러 멈추고 "버전 끝자리를 올릴까요?" 하고 묻습니다. 값만 바꿨으면 "응"이라고 답하세요. 여러분
  6. 검문소를 돌리고, 통과하면 저장하고 GitHub에 올립니다.
  7. 결과 보고를 읽고 화면을 확인합니다. 여러분
확인할 것 · 가이드 사이트 Semantic 페이지에서 색이 바뀌었는지. Figma에 반영하는 방법은 Figma에서 확인에 있습니다.

새 토큰·새 글자 스타일 추가하기

없던 것을 새로 만들 때
이렇게 말하세요
경고 배경색 토큰을 새로 추가해줘. 라이트는 orange/50, 다크는 orange-dark/100 으로
  1. Claude가 비슷한 토큰이 이미 있는지, 이름이 규칙에 맞는지 확인합니다.
  2. "이 이름으로 추가할까요?" 질문에 분명한 문장으로 답합니다. 여러분
  3. 여러분이 한 말을 그대로 인용해서 승인 기록을 남깁니다. 기계가 대화 기록에 그 문장이 실제로 있는지 대조합니다.
  4. 원본에 추가 → 한 번에 다시 만들기 → 검문소 → 저장·업로드.
미리 알아둘 것 · "응", "그래" 같은 짧은 답도 되지만, 바로 앞 질문과 짝이 맞아야 통과합니다. 헷갈리면 "경고 배경색 토큰 추가해" 처럼 무엇을 승인하는지 넣어 말하세요. 승인 문장 없이 새 항목이 들어가면 검문소가 저장을 막습니다.

부품의 모양 바꾸기

크기·여백·상태·쓰는 색을 바꿀 때
이렇게 말하세요
버튼 MD 크기 높이를 44에서 40으로 바꿔줘
  1. 컴포넌트 설계도 원본에서 해당 부분을 찾아 보여 줍니다.
  2. 계획 확인 후 OK. 여러분
  3. 설계도를 고칩니다.
  4. 고친 Claude와 다른 검사 담당 Claude가 원본과 대조해 검증합니다. 이 검증 도장이 없으면 저장이 안 됩니다. 값 한 개만 바꾸는 단순 수정은 예외로, 경고만 남기고 통과합니다.
  5. 한 번에 다시 만들기 → 설치기·안내 모델·AI 문서가 새로 만들어집니다.
  6. 검문소 → 저장·업로드.
  7. Figma와 사이트에서 확인합니다. 여러분
미리 알아둘 것 · 가이드 사이트의 Components 페이지와 웹 UI 키트는 이 흐름에서 자동으로 안 바뀝니다. 웹 키트까지 반영하려면 다음 카드의 "웹 업데이트 해줘"를 이어서 요청하세요.

웹 UI 키트에 반영하기

개발자가 받는 코드까지 바꿀 때
이렇게 말하세요
버튼 웹 업데이트 해줘
  1. 지금 상태와 원본을 전부 대조해 무엇이 다른지 정리합니다.
  2. 원본에 근거가 없는 항목이 있으면 멈추고 질문합니다.
  3. 코드 담당 Claude가 웹 코드를 만듭니다.
  4. 자동 검사를 전부 통과시키고, PC·모바일 × 라이트·다크 화면을 찍어 둡니다.
  5. 검수 화면을 열어 보고 "승인"합니다. 여러분
  6. 버전 번호를 올리고 다운로드 페이지의 키트를 새것으로 바꿉니다.
확인할 것 · 가이드 사이트 다운로드 페이지에 새 버전 번호가 보이는지. 부품 이름 없이 "웹 업데이트 해줘"만 하면 하던 작업을 이어 하거나 어떤 부품인지 되묻습니다.

  2. AI용 문서와 다운로드 페이지를 다시 만듭니다.
  3. 검문소 → 저장·업로드.
  4. 결과를 확인합니다. 여러분

Figma에서 확인

고쳤는데 Figma에는 옛날 모습일 때

설치기는 같은 이름의 부품이 이미 있으면 건너뜁니다. 이미 화면에 배치해 둔 부품이 끊기지 않게 하려는 장치입니다. 그래서 원본을 고쳐도 이미 설치된 Figma 파일에는 옛 모습이 남습니다.

방법어떻게주의
그 부품만 다시해당 부품 세트와, 그 옆의 다크모드 견본 판(이름 끝이 "Spec Dark")을 지우고, 설치기에서 그 부품만 골라 [선택 항목 설치]안전. 보통 이걸 씁니다
전부 다시설치기의 [재설치] → [재설치 시작]전부 지우고 새로 깔아서, 화면에 배치해 둔 부품 연결이 끊길 수 있습니다

설치기는 매번 같은 자리에 덮어써지므로 Figma에 플러그인을 다시 등록할 필요는 없습니다. 새 모습이 안 보이면 등록 문제가 아니라 위의 건너뛰기를 먼저 의심하세요. Figma에서 다크로 바꿨는데 일부가 안 바뀌면, 그 부품에 라이트 모드가 고정으로 걸려 있는 경우가 많습니다. "이 부품 라이트 고정 풀어줘"라고 하세요.

토큰 값만 바꿨을 때. 변수는 같은 이름 그대로 값만 새로 쓰도록 만들어져 있어서, 설치기에서 변수 항목을 다시 설치하면 됩니다. 이 동작은 아직 끝까지 확인하지 못했으니, 반영 후 "Figma 변수 값이 바뀌었는지 확인해줘"라고 한 번 요청하세요.

하루 작업 순서

한 건을 처음부터 끝까지

  1. 새 대화 열기Claude 앱 Code 탭에서 이 프로젝트 폴더로 새 대화
  2. "별도 폴더에서 해줘"고치는 작업은 첫마디에 이렇게. 질문만 할 때는 필요 없습니다
  3. 목표만 말하기무엇을 바꾸고 싶은지만. 숫자·방법은 Claude가 원본에서 찾습니다
  4. 계획 OK 한 번계획을 보고 OK. 새 항목 승인이나 웹 키트 검수가 있으면 중간에 한 번 더 묻습니다
  5. "합쳐줘"결과를 보고 이렇게 말하면 본 폴더에 합치고 GitHub에 올립니다

여러 건을 동시에 하려면 대화를 여러 개 열고 각각 "별도 폴더에서 해줘"라고 하면 됩니다. 끝난 대화를 합치지 않고 오래 내버려 두면 나중에 합칠 때 부딪힐 수 있으니, 끝나면 바로 합치세요.

Claude가 질문을 올리면 그건 정말 사람이 정해야 하는 것입니다. 질문에는 "무엇을, 왜, 선택지, 안 정하면 어떻게 되는지"가 함께 옵니다.

안전장치와 금지

이것만은 하지 마세요

대부분은 검문소가 자동으로 막지만, 사람이 요청해서 생기는 실수도 있습니다.

  • 결과물을 직접 고쳐 달라고 하기"사이트의 이 색 코드만 바꿔줘"가 아니라 "이 토큰 값 바꿔줘". 결과물만 고치면 다음 생성 때 되돌아갑니다.
  • 검문소를 건너뛰고 저장하기저장이 막히면 막힌 이유를 고칩니다. 건너뛰는 옵션은 쓰지 않습니다.
  • 화면에 색 코드 직접 쓰기모든 색은 Semantic 토큰을 거칩니다. 반투명 덮개 한 가지만 예외입니다.
  • 레거시나 운영 서비스 화면 값을 새 기준에 섞기DS 2.4와 모두앱 같은 서비스 화면은 참고만 합니다. 거기 숫자를 새 기준의 근거로 쓰지 않습니다.
  • 버튼 Danger 종류 다시 추가하기삭제가 확정된 항목입니다.
  • "레거시랑 다르니 틀렸다"고 단정하기레거시가 낡았을 수 있습니다. 애매하면 Claude가 묻습니다.

자주 생기는 상황

원본을 고쳤는데 Figma에 안 바뀌어 보여요
설치기가 이미 있는 부품을 건너뛴 경우입니다. Figma에서 확인의 "그 부품만 다시"를 하세요.
저장(커밋)이 막혔다고 해요
Claude에게 "검문소에서 뭐가 막혔는지 쉽게 알려주고 고쳐줘"라고 하세요. 대부분 다시 만들기 한 번으로 풀립니다. 새 항목 승인 문제라면 승인 문장을 달라고 질문이 올라옵니다.
웹 키트 만들기가 중간에 멈췄어요
토큰 값이 바뀌면 일부러 멈추는 단계입니다. 값만 바뀌었으면 끝자리 +1, 부품이 추가되거나 쓰는 법이 바뀌었으면 가운데 자리 +1로 버전을 올리면 이어집니다. "웹 키트 버전 올려줘"라고 하세요.
AI용 공개 가이드가 며칠째 안 바뀌어요
공개 저장소는 매일 새벽 3시 15분에 이쪽 내용을 가져간 뒤 자체 검사를 돌립니다. 검사가 실패하면 알림 없이 조용히 멈춥니다(예전에 13일 연속 멈춘 적 있음). "공개 가이드 저장소 동기화가 실패하고 있는지 확인해줘"라고 하세요.
합치려는데 부딪혔다고 해요
자동으로 만들어지는 파일끼리 부딪힌 거면 Claude가 다시 만들어서 풉니다. 원본끼리 부딪혔을 때만 어느 쪽을 남길지 물어봅니다.
예전 부품 이름이 지금 무엇인지 모르겠어요
"레거시 이름 ○○는 지금 무슨 부품이야?"라고 물으세요. 대응표에서 찾아 주고, 아직 정해지지 않은 거면 마음대로 정하지 않고 그렇다고 알려 줍니다.
Claude가 같은 실수를 반복해요
반복 요청은 따로 기록되고, 같은 게 3번 쌓이면 규칙으로 만들자고 제안이 올라옵니다. "이거 반복 요청으로 기록해줘"라고 해도 됩니다.
스크린샷에 아이콘이 비어 보여요
페이지를 파일로 직접 열면 아이콘이 안 그려집니다. "가이드 사이트 열어줘"라고 하면 제대로 된 주소(localhost:4173)로 엽니다.
