river 목표(2026-09-08 확인): 앞으로 **패턴(화면 단위 조립)도 우리 패턴으로 만들고, 퍼블리셔 개입 없이 화면을 완성**하는 것이 UI 라이브러리의 지향점이다. 저장소 계약서에는 패턴 구현·문구 규칙만 있고 이 목표 자체는 기록돼 있지 않다.

**Why:** 이 목표가 있으면 "컴포넌트는 우리 것 / 배치는 서비스(퍼블리셔) 것"이라는 경계가 임시 상태라는 뜻이다. 배치·간격도 결국 우리 칸(`data-s1-*`)으로 내려와야 한다.

**How to apply:** 배포본을 설계할 때 "퍼블리셔가 알아서 조립할 것"으로 남기지 말고, 반복되는 배치는 패턴으로 승격해 우리가 제공하는 방향으로 제안한다. class 칸은 서비스 몫으로 열어두되, 그 칸에 남는 일이 늘어나면 승격 후보로 본다. 관련: [[github-guideline-repo-distribution]]
