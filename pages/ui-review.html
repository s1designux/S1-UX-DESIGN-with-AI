직접 확인하는 방법

  1. Tab 키로 입력칸에 들어가면 테두리가 파랗게 바뀌고 커서가 값 끝에 놓이는지 확인합니다(오류·정상확인·읽기전용에서도 같습니다). 마우스로 누르면 누른 자리에 커서가 놓이고, 비활성 칸은 건너뜁니다. Button의 초점 표시는 브라우저 기본 표시를 그대로 씁니다.
  2. Button 위에 마우스를 올리고 눌러서 Hover·Pressed 반응을 확인합니다.
  3. Input에 직접 입력해 remove 아이콘이 나타나는지, 아이콘 위 Hover 배경과 누른 뒤 값 삭제·초점 복귀를 확인합니다.
  4. Password Field는 눈 아이콘을 눌러 표시/숨김이 바뀌고 아이콘(감김↔뜬눈)·이름(보기↔숨기기)이 함께 바뀌는지, 누른 뒤 초점이 입력칸으로 돌아오는지 확인합니다.
  5. Search Input은 값을 입력한 뒤 Enter 와 돋보기 클릭 둘 다 검색 실행 문구가 뜨는지, 값이 있을 때만 지우기가 나타나고(초점과 무관) 돋보기는 항상 보이는지 확인합니다.
  6. Checkbox·Radio는 상자만 있는 기본형과 라벨이 붙은 형태를 나란히 놓았습니다. 라벨을 눌러도 선택되는지, 라디오는 화살표 키로 옮겨지는지 확인합니다.
  7. Toggle은 눌러서 켜고 끄고, Tab·Space로도 바뀌는지 확인합니다. 비활성은 눌러도 바뀌지 않아야 합니다.
  8. Chip은 눌러서 선택하고 다시 눌러 해제되는지, Line·Solid의 선택 표시가 구분되는지 확인합니다.
  9. Select는 트리거를 눌러 목록을 열고, 화살표 키·Enter로 고른 뒤 값이 트리거에 들어오는지 확인합니다. 바깥을 누르면 닫힙니다.
  10. Dropdown 목록은 글자 유형과 체크박스 유형 두 가지입니다. 체크박스 유형은 여러 개를 함께 고를 수 있고, 「전체 선택」 아래에는 구분선이 있습니다.
  11. Filter Chip은 눌러서 열고(Selected), 값을 고르면 닫히며 값이 칩에 남습니다(Complete). Esc로도 닫히는지 확인합니다.
  12. Textarea는 직접 입력해 Focus 색과 세로 크기 조절(오른쪽 아래 끌기)을 확인합니다. 가로로는 늘어나지 않아야 합니다.
  13. Multi Toggle은 칸을 눌러 선택이 옮겨지는지, 화살표 키로도 이동하는지 확인합니다. 선택된 칸의 양옆 경계가 겹쳐 보이지 않아야 합니다.
  14. GNB는 메뉴 글자 위에 마우스를 올려 파란 글자와 아래 밑줄이 생기는지, 이미 표시된 「홈」과 같은 모양인지 확인합니다. Tab으로는 로고 → 메뉴 → 언어 → 계정 → 전체메뉴 순으로 넘어갑니다.
  15. PC와 Mobile, Light와 Dark에서 같은 의미와 우선순위로 보이는지 비교합니다.

아직 river 승인 전인 항목입니다. 이번 검수에서 봐 주세요.

1. Base Input

안내 문구는 선택 사항입니다. Focus에서는 값이 있을 때 remove 아이콘이 나타나며, PC에서는 아이콘 위에 마우스를 올리면 해당 누르는 영역에만 Hover 배경이 생깁니다.

1b. Password Field (Input 옵션)

별도 컴포넌트가 아니라 Base Input 조립입니다 — type=password + 눈 액션. 누르면 표시/숨김이 전환되고 Input으로 초점이 돌아옵니다. 트레일 순서는 [눈][지우기](2px 간격)입니다. 크기·상태·break는 Base Input과 동일합니다.

1c. Search Input (Input 옵션)

별도 컴포넌트가 아니라 Base Input 조립입니다 — data-mode="search" + 돋보기 액션(항상 표시). 상태는 Default·값 있음(지우기+돋보기)·Disabled 3종뿐입니다. 돋보기 클릭 또는 Enter 키 둘 다 s1:input:search 이벤트를 냅니다 — 아래에서 직접 입력하고 Enter를 눌러 확인하세요.

2. Button

Primary·Secondary·Blue Line의 크기와 상태를 비교합니다. Hover·Pressed는 실제 마우스로 확인합니다.

3. Checkbox

정본 상태 5종을 그대로 옮겼습니다. 라벨은 선택 부품이라 없는 형태가 기본이고, 붙이면 라벨을 눌러도 선택됩니다. 부분선택(중간 상태)은 정본에 없어 이번 배포에 넣지 않았습니다.

4. Radio

정본 상태 5종 × 라벨 유무를 그대로 옮겼습니다. 같은 그룹은 하나만 선택되고, 그룹 안에서는 화살표 키로 이동합니다.

5. Toggle

정본 4가지(켜짐·꺼짐 × 기본·비활성)를 그대로 옮겼습니다. 정본에 마우스오버 변형과 움직임(애니메이션)이 없어 웹에도 넣지 않았습니다. 크기 축이 없어 40×20 고정입니다.

6. Chip

Line·Solid × 상태 4종입니다. 크기는 정본에 있는 조합만 만들었습니다 — PC는 SM 28px·MD 34px, Mobile은 SM 30px. 필터 칩(드롭다운·완료 상태)과 아이콘·닫기(X)는 이번 범위가 아닙니다.

7. Select Box

정본 상태 5종(Default·Hover·Open·Filled·Disabled) × 크기 4종(PC XXSM 28 · XSM 34 · MD 44 / Mobile MD 48)입니다. Hover는 마우스를 올려 확인합니다. 열린 목록은 Dropdown 배포본을 그대로 조립한 것이라 목록 자체의 모양은 8번에서 봅니다. 정본에 Open과 별개인 Focus 축과 Error 상태가 없어 만들지 않았습니다.

8. Dropdown (목록 패널 + 옵션 행)

Select·Filter Chip이 열었을 때 나오는 목록입니다. 유형 3가지(글자 · 체크박스 · 체크박스+전체 선택) × 크기 3종(XXSM 28 · XSM 34 · MD 44)이고 옵션 행 상태는 Default·Hover·Selected입니다. 패널 자체에는 상태 축이 없습니다(항상 Default). 「전체 선택」의 부분선택(중간 상태)은 정본에 없어 만들지 않았습니다.

9. Filter Chip

Line·Solid × 제목 있음/없음 × 상태 5종(Default·Hover·Selected(열림)·Complete(값 확정)·Disabled) × 크기 3종(PC SM 28 · MD 34 / Mobile MD 30)입니다. Hover는 마우스로 확인합니다. Complete는 정본에서 Default와 같은 색을 씁니다 — 값 문구만 달라집니다. 열었을 때 목록 크기는 Select와 다르게 SM·MD 모두 XSM(34px)으로 붙습니다. 다중 선택과 Error는 정본에 없어 만들지 않았습니다.

10. Textarea

정본 상태 5종(Default·Focus·Filled·Disabled·Read-only)을 그대로 옮겼습니다. Focus는 직접 눌러 입력해 확인합니다. 크기 축이 없어 PC·Mobile 모양이 같고, 폭은 놓인 자리를 채우며 세로 방향으로만 크기를 조절할 수 있습니다(river 결정 2026-09-02). 라벨·안내 문구·글자수 세기는 정본에 없어 만들지 않았습니다 — 이름은 화면에서 label 또는 aria-label로 연결합니다.

11. Multi Toggle

정본 상태 4종(Default·Hover·Selected·Disabled) × 두 크기(MD 44px · SM 34px)입니다. Hover는 마우스를 올려 확인합니다. 한 번에 하나만 선택되고 화살표 키로 이동합니다. 정본에 모바일 크기가 없어 PC 전용이며, 예시는 정본과 같은 3칸입니다.

12. Modal

정본 변형 4가지(PC·Mobile × 버튼 1개(Single)·2개(Dual))를 그대로 옮겼습니다. 정본에 hover·비활성 같은 상태 축이 없어 상태 표본 대신 변형 표본을 봅니다. PC만 제목 옆 닫기(X)가 있고 Mobile에는 없습니다(정본 그대로). 어두운 배경(딤)은 등록부가 가진 부품이라 함께 넣었습니다. 아래 표본은 지면에 눕혀 보여주는 검수 표시이고, "실제로 열어보기"가 진짜 팝업입니다 — Esc로 닫히고 Tab은 팝업 안에서만 돕니다.

13. Table

정본 상태 3종(기본·Hover·선택) × 세 크기(MD 44 · SM 38 · XSM 34, XSM만 글자 12)입니다. 상태는 정본과 같이 셀이 가지고 행은 그 조합으로 보여집니다. 선택 컬럼은 승인된 Checkbox 배포본을 그대로 쓰고, 표 아래 페이지 이동과 '몇 개씩 보기'도 각각 Pagination·Select Box 배포본을 조립한 것입니다(river 결정 2026-09-02) — Table은 표만 가집니다. 정렬(소트) 기능은 정본에 없어 만들지 않았습니다. 정본에 모바일 표출 규칙이 없어 PC 전용입니다.

14. Mobile Bottom Nav

배포 부품은 탭 아이템 1칸(60×60)뿐입니다 — 4탭 바는 정본·등록부 둘 다 컴포넌트가 아니라고 명시합니다(river 결정). 상태는 unselected·selected 2가지뿐이고 hover·disabled는 정본에 없어 만들지 않았습니다. root 자체가 role=tab이며 role=tablist 컨테이너는 화면이 조립합니다. 크기 축·JavaScript는 필요 없습니다(jsRequired=false).

15. Mobile Header

river 결정(D5)으로 상태바(StatusBar)·Platform 축을 뺐습니다 — AppBar 56px만 배포합니다. Type 6종(Home/Title · Home/Title+Subtitle+1Icon · Standard/Title · Standard/Title+Close · Standard/No Title · Standard/No Title+Close)이 유일한 축입니다. 삭제된 'Home / Title + 2 Icons'는 만들지 않았습니다. No Title 계열은 제목 텍스트가 없어 본문의 h1이 화면의 주 제목 역할을 합니다. 알림 아이콘은 2색(본체 gray-dark + 신규 점 red)이라 CSS 마스크 2겹으로 표현합니다. 크기 축·JavaScript는 필요 없습니다(jsRequired=false).

16. Time Picker

정본 상태 5종(Default · Hover · Focus · Filled · Disabled)이며 Focus = 목록이 열린 상태입니다(정본 buildTimePicker). 값은 확인을 눌러야 트리거에 남습니다. 유형은 24시간제(시·분 2열) · 오전오후(오전오후·시·분 3열) 2가지입니다. river 결정(D1)으로 모바일 휠 바텀시트는 이번 범위 밖이라 모바일도 같은 목록 드롭다운을 쓰고 트리거만 48px입니다 — 휠 시트는 Date Picker 작업에서 함께 만듭니다. 분 목록 기본은 1분 단위이고 data-minute-step으로 조절합니다(D2). 정본에 Error 상태는 없습니다.

17. Date Picker

정본 상태 4종(Default·Filled·Open·Disabled) + 웹에서만 더한 Hover 1종(정본 Date Picker 세트에 마우스오버 상태가 없습니다 — river 승인 대기) × PC 3크기(XXSM 28·XSM 34·MD 44). Hover는 마우스를 올려 확인합니다. 패널은 Date·Year·Month 3화면(build-components.ts buildCalendar)이고, 달력 크기는 입력창을 따라갑니다 — MD 입력창은 큰 달력(356×352), XSM·XXSM 입력창은 작은 달력(267×266)이 열립니다(river 지시 2026-09-04로 신설, 아래 크기별 Open 표본에서 확인). 헤더 라벨은 연도·월을 각각 누를 수 있게 둘로 나눴습니다(D5). 요일은 일요일 시작입니다(D3 — 시각 정본은 월요일 시작이라 갈라진 지점, CU-1로 기록). 기간 선택은 시작일만 고른 상태에서 커서까지 미리 칠해집니다(D6). Mobile은 팝오버 대신 하단 시트가 열립니다(M7).

18. Assist Button

Button과 별개 컴포넌트입니다(river 결정 2026-09-08). 정본 상태 4종(Default·Hover·Pressed·Disabled)이며 Pressed는 Hover와 같은 모양입니다(코어 Button과 같은 규칙). 크기 축이 없어 높이 32px 고정입니다.

19. Text Button

Button과 별개 컴포넌트입니다(river 결정 2026-09-08). 배경·테두리가 없고 Primary·Secondary 두 색만 있습니다. Hover·Pressed는 색이 바뀌지 않고 밑줄만 붙습니다. 크기 축이 없습니다.

20. Modal Content

확인 계열 Modal과 별개 컴포넌트입니다. 정본 변형 6가지(Size MD·LG·XL × Footer Single·Dual)를 그대로 옮겼습니다. 본문은 정본과 같은 회색 자리표시("컨텐츠 영역")이고, 실제 화면에서는 이 자리를 입력창·표·이미지로 바꿔 넣습니다. 높이는 고정이 아니라 최소값입니다 — 콘텐츠가 늘면 패널이 커지다가 화면의 85%에서 멈추고, 그 뒤로는 본문(회색 영역) 안에서만 스크롤됩니다(제목·버튼은 항상 보입니다). PC 전용입니다.
